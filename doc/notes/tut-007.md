# Summarize this video

الفيديو يكمّل بناء mini-RAG عبر تنظيم العمل مع MongoDB بشكل **احترافي** باستخدام الـ indexing، والـ models، والـ Docker.[^1_1]

## هدف الحلقة

- ضبط MongoDB داخل Docker مع user/password عن طريق env variables وملف ‎.env و ‎.env.example، مع توثيق ذلك في README وتوضيح مشاكل شائعة في docker-compose (volumes, parsing).[^1_1]
- تجهيز قاعدة البيانات لتكون قابلة للتوسع (scalable) مع زيادة حجم البيانات، عن طريق تعريف سكيمات واضحة وإنشاء فهارس (indexes) مناسبة.[^1_1]


## Mongo Indexing في المشروع

- يشرح مشكلة البحث عن كل الـ chunks لبروجيكت معيّن وكيف أن المرور على مليون سجل بدون index مثل كتاب بلا فهرس، ثم يقدّم مفهوم الـ index كفهرس سريع على حقل مثل `chunk_project_id`.[^1_1]
- يعرّف بنية index في Mongo: قائمة مفاتيح (fields) مع نوع الترتيب (1 تصاعدي، ‎-1 تنازلي) وخصائص مثل `unique`، مع أمثلة على single-field index وcompound index (مثلاً project_id + order).[^1_1]


## Static methods + async initialization

- يبني static methods في طبقة الـ DB schema (Pydantic) للحصول على قائمة بالـ indexes لكل collection (مثل projects, data_chunks, assets) باستخدام decorator `@staticmethod` و`@classmethod`.[^1_1]
- في طبقة الـ models يعرف دالة async مثل `init_collection` تتصل بـ Mongo عبر Motor، تتحقق هل الـ collection موجودة، ثم تنشئ الـ indexes المعرفة في الـ schema باستخدام `create_index`، مع التعامل مع كون العمليات async بالكامل.[^1_1]


## حل مشكلة async في `__init__`

- يوضّح أن `__init__` لا يمكن أن تكون async، ولا يمكن استدعاء دوال async بداخلها مباشرة، فينشئ دالة وسيطة static (مثل `create_instance`) تستدعي تهيئة الـ collection (إنشاء indexes) ثم تُرجع الـ instance النهائي.[^1_1]
- يطبّق نفس النمط على أكثر من model (ProjectModel, DataChunkModel) حتى لا ينسى المستخدم استدعاء دوال التهيئة ويضمن دائماً وجود الـ indexes قبل إدخال البيانات.[^1_1]


## إنشاء Collection جديدة للـ Assets

- يضيف collection جديدة اسمها `assets` (resources) لتخزين metadata عن مصادر المشروع (ملفات، روابط، …) مع حقول مثل: project_id (ObjectId)، kind/type، name، path أو URL، size، و `ts_pushed` (تاريخ الإدخال بـ `datetime.utcnow`).[^1_1]
- يعرّف عدة indexes لهذه الـ collection: على `project_id` وحده، وعلى combination من `project_id + name` كـ unique لتفادي تكرار نفس الاسم لنفس المشروع، ما يسهّل queries لاحقة.[^1_1]


## ربط الـ API بالـ Assets

- يعدّل مسار رفع الملف (upload route) بحيث بعد رفع الملف وتحديد `file_path` و`file_id` يقوم بإنشاء Asset object من سكيمة `AssetSchema` ويستدعي `AssetsModel.create(asset)` لحفظه في Mongo مع حساب حجم الملف عبر `os.path.getsize`.[^1_1]
- يضيف دوال للحصول على كل الـ assets الخاصة ببروجيكت معيّن (`get_by_project_id`) مع تحويل الـ project_id النصي إلى `ObjectId` بأمان، ومعالجة الفروق بين تمثيل ObjectId في Mongo وJSON.[^1_1]


## تنبيهات عملية ونصائح

- يبيّن أوامر تنظيف Docker أثناء التطوير: إيقاف كل الـ containers، حذفها، حذف الـ images، وحذف الـ volumes ثم `docker system prune --all` للبدء من الصفر عند حدوث مشاكل.[^1_1]
- ينهي الحلقة بنصائح عن ملفات ‎.env و docker-compose: استخدام double quotes للـ strings، تجنب `#` في القيم لأن بعض parsers يعدّها comments، ويؤكد أن ما يُبنى هنا pattern قوي يناسب مشاريع production حقيقية في الـ RAG.[^1_1]

## 3. Static / Class Methods في Schemas للـ Indexes

### الفكرة

- لكل collection عندك Pydantic schema في `db.schemas`.[^2_1]
- عايز مكان واحد يوصف كل الـ indexes بتاعة collection دي.[^2_1]
- بيعمل method `@classmethod` أو `@staticmethod` ترجع list من مواصفات الـ indexes.[^2_1]


### مثال: ProjectSchema

```python
from pydantic import BaseModel, Field
from typing import List, Dict, Any

class ProjectSchema(BaseModel):
    id: str | None = Field(alias="_id", default=None)
    name: str
    description: str | None = None

    @classmethod
    def get_indexes(cls) -> List[Dict[str, Any]]:
        return [
            {
                "keys": [("name", 1)],
                "name": "project_name_index_1",
                "unique": True,
            },
        ]

    class Config:
        allow_population_by_field_name = True
```

## 4. دالة async لتهيئة الـ collection وإنشاء الـ indexes

### الفكرة

- في layer `db.models` عندك class لكل collection بيتعامل مع Motor.[^2_1]
- تضيف method `async def init_collection(cls, db_client)` تعمل:
    - تشيك لو collection موجودة ولا لأ.
    - لو مش موجودة:
        - تـ create collection
        - تـ create كل indexes اللي راجعة من `Schema.get_indexes()`.[^2_1]


### مثال: ProjectModel

```python
from motor.motor_asyncio import AsyncIOMotorClient, AsyncIOMotorCollection

class ProjectModel:
    collection_name = "projects"

    def __init__(self, collection: AsyncIOMotorCollection):
        self.collection = collection

    @classmethod
    async def init_collection(cls, db_client: AsyncIOMotorClient) -> "ProjectModel":
        db = db_client[settings.mongo_db_name]
        existing = await db.list_collection_names()
        if cls.collection_name not in existing:
            await db.create_collection(cls.collection_name)

        coll = db[cls.collection_name]

        # إنشاء الـ indexes
        for index in ProjectSchema.get_indexes():
            await coll.create_index(
                index["keys"],
                name=index.get("name"),
                unique=index.get("unique", False),
            )

        return cls(coll)
```

نفس النمط بيتطبق لـ `DataChunkModel` و `AssetsModel` بعدين.[^2_1]

## 5. مشكلة إن __init__ ماينفعش تبقى async وحل create_instance

### المشكلة

- عايز في أول استخدام للـ model تعمل `await init_collection()` لكن `__init__` نفسها ماينفعش تبقى async.[^2_1]


### الحل

- تعمل static/class method وسيطة اسمها مثلاً `create_instance` هي اللي تبقى async:[^2_1]

```python
class ProjectModel:
    collection_name = "projects"

    def __init__(self, collection: AsyncIOMotorCollection):
        self.collection = collection

    @classmethod
    async def create_instance(cls, db_client: AsyncIOMotorClient) -> "ProjectModel":
        return await cls.init_collection(db_client)
```

وبدلاً من:

```python
project_model = ProjectModel(db_client)  # قديمة
```

تبقى:

```python
project_model = await ProjectModel.create_instance(db_client)
```

فأي مكان في الـ routes أو الخدمات يستعمل الباترن ده، وبالتالي تتأكد أن الـ indexes تظبطت قبل ما البيانات تتكتب.[^2_1]

## 6. Collection جديدة للـ Assets (resources)

### الفكرة

- بدل ما تعتمد على file_id فقط، تعمل collection `assets` تخزن فيها metadata عن كل ملف/مصدر:
    - project_id
    - type/kind (file, url, …)
    - name (اسم الملف)
    - path أو url
    - size
    - ts_pushed (وقت الإدخال)[^2_1]


### Schema: AssetSchema

```python
from pydantic import BaseModel, Field, conint, constr
from datetime import datetime
from bson import ObjectId
from typing import List, Dict, Any

class PyObjectId(ObjectId):
    @classmethod
    def __get_validators__(cls):
        yield cls.validate

    @classmethod
    def validate(cls, v):
        if isinstance(v, ObjectId):
            return v
        return ObjectId(str(v))

class AssetSchema(BaseModel):
    id: PyObjectId | None = Field(alias="_id", default=None)
    project_id: PyObjectId
    kind: constr(strip_whitespace=True, min_length=1)  # "file" | "url" | ...
    name: constr(strip_whitespace=True, min_length=1)
    path: str | None = None
    size: conint(ge=0) = 0
    ts_pushed: datetime = Field(default_factory=datetime.utcnow)

    @classmethod
    def get_indexes(cls) -> List[Dict[str, Any]]:
        return [
            {
                "keys": [("project_id", 1)],
                "name": "asset_project_id_index_1",
                "unique": False,
            },
            {
                "keys": [("project_id", 1), ("name", 1)],
                "name": "asset_project_id_name_index_1",
                "unique": True,
            },
        ]

    class Config:
        json_encoders = {ObjectId: str}
        allow_population_by_field_name = True
```


### Model: AssetsModel

```python
from motor.motor_asyncio import AsyncIOMotorClient, AsyncIOMotorCollection

class AssetsModel:
    collection_name = "assets"

    def __init__(self, collection: AsyncIOMotorCollection):
        self.collection = collection

    @classmethod
    async def init_collection(cls, db_client: AsyncIOMotorClient) -> "AssetsModel":
        db = db_client[settings.mongo_db_name]
        existing = await db.list_collection_names()
        if cls.collection_name not in existing:
            await db.create_collection(cls.collection_name)

        coll = db[cls.collection_name]

        for index in AssetSchema.get_indexes():
            await coll.create_index(
                index["keys"],
                name=index.get("name"),
                unique=index.get("unique", False),
            )

        return cls(coll)

    @classmethod
    async def create_instance(cls, db_client: AsyncIOMotorClient) -> "AssetsModel":
        return await cls.init_collection(db_client)

    async def create(self, asset: AssetSchema) -> AssetSchema:
        data = asset.dict(by_alias=True, exclude_unset=True)
        result = await self.collection.insert_one(data)
        asset.id = result.inserted_id
        return asset

    async def get_by_project_id(self, project_id: str) -> list[AssetSchema]:
        # تحويل string إلى ObjectId بأمان
        oid = PyObjectId(project_id)
        cursor = self.collection.find({"project_id": oid})
        docs = await cursor.to_list(length=None)
        return [AssetSchema(**doc) for doc in docs]
```


## 7. ربط route الرفع بالـ Assets

### الفكرة

- في route `/upload` بعد ما ترفع الملف وتحسب `file_path` و `file_id`، تنشئ Asset وتخزنه.[^2_1]


### مثال (FastAPI route)

```python
from fastapi import APIRouter, UploadFile, File, Form, Depends
import os

router = APIRouter()

@router.post("/upload")
async def upload_file(
    project_id: str = Form(...),
    file: UploadFile = File(...),
    db_client: AsyncIOMotorClient = Depends(get_mongo_client),
):
    # 1) حفظ الملف في disk
    file_bytes = await file.read()
    save_dir = "storage/uploads"
    os.makedirs(save_dir, exist_ok=True)
    file_path = os.path.join(save_dir, file.filename)
    with open(file_path, "wb") as f:
        f.write(file_bytes)

    file_size = os.path.getsize(file_path)

    # 2) إنشاء AssetSchema
    asset_schema = AssetSchema(
        project_id=project_id,  # هيتم تحويلها لـ ObjectId
        kind="file",
        name=file.filename,
        path=file_path,
        size=file_size,
    )

    # 3) حفظ asset في Mongo
    assets_model = await AssetsModel.create_instance(db_client)
    asset_record = await assets_model.create(asset_schema)

    # تقدر ترجع file_id أو asset_id أو كليهما
    return {
        "asset_id": str(asset_record.id),
        "project_id": project_id,
        "filename": file.filename,
    }
```
