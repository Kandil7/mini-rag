# Summarize this video

هذا الفيديو حلقة تطبيقية لتحسين **data pipeline** في مشروع mini-RAG قبل الانتقال لمرحلة الـ LLM نفسها.[^1_1]

## فكرة الحلقة

- الهدف هو تحسين طريقة تخزين ومعالجة الملفات (assets) في MongoDB بحيث يمكن التعامل مع أكثر من ملف لكل مشروع، وتجهيز كل ذلك لمرحلة ربطها بالـ RAG لاحقًا.[^1_1]
- التركيز على جعل التعديلات “incremental” بدون إعادة كتابة المشروع من الصفر، مع الحفاظ على تصميم نظيف يسهل التطوير المستقبلي.[^1_1]


## تحسين الـ Assets Model

- إضافة كولكشن assets في الداتابيز لتخزين موقع كل ملف ونوعه (type) بدل افتراض أن المصدر دائمًا ملف واحد فقط، مع دعم أنواع مستقبلية مثل URL أو streams.[^1_1]
- تعديل دوال الـ model بحيث يمكن جلب كل الـ assets لمشروع معيّن مع فلترة بالـ type، وتحويل نتائج Mongo إلى Pydantic models بدل التعامل المباشر مع dicts الخام.[^1_1]


## تطوير Endpoint المعالجة (process)

- جعل `file_id` (اسم الملف) باراميتر اختياري:
    - لو أُرسل → تُعالج فايل واحد محدد.
    - لو لم يُرسل → يُجلب كل الملفات الخاصة بالمشروع من كولكشن assets ويتم عمل loop عليها.[^1_1]
- توحيد منطق المعالجة بحيث يتم التعامل دائمًا مع قائمة من الملفات (حتى لو تحتوي ملفًا واحدًا) لتبسيط الكود وتقليل التكرار في الـ if/else.[^1_1]


## فحوصات السلامة والـ Logging

- إضافة validation للتأكد من وجود الملف فعليًا على الـ filesystem قبل محاولة تحميله (باستخدام `os.path.exists`) ثم التعامل مع حالات الـ `None` في `get_file_content` بشكل صريح.[^1_1]
- استخدام logger بدل `print` لكتابة رسائل error عند فشل معالجة ملف معيّن، مع الاستمرار في معالجة باقي الملفات وفقًا لسيناريو عمل يختاره الـ business logic (مثلاً: تخطي الملف المعطوب مع تسجيل تحذير).[^1_1]


## تحديث الـ Data Schema للـ Chunks

- تعديل سكيمة `data_chunk` بحيث تحتوي على حقل `chunk_asset_id` (ObjectId) يربط كل chunk بالـ asset الأصلي في كولكشن assets، بالإضافة إلى الـ metadata التي تحتوي على `source` (مسار الملف).[^1_1]
- بعد التعديلات يصبح بالإمكان معرفة: من أي ملف جاء كل chunk، وما هو الـ asset (بالـ ObjectId) المرتبط به، مما يسهل لاحقًا عمليات الاسترجاع والتحليل على مستوى الملف.[^1_1]


## معالجة حالات الحافة (Edge Cases)

- التعامل مع حالة إرسال `file_id` غير موجود في الـ DB، بإرجاع JSON Response بخطأ واضح (مثل `file_id_error`) مع status code 400.[^1_1]
- التعامل مع حالة عدم وجود أي ملفات في المشروع (أو أن نتيجة البحث فارغة) برسالة خطأ `no_files_error` توضح أن لا يوجد ما يمكن معالجته.[^1_1]

إذا أحببت، يمكن استخراج pseudo-code مختصر من الحلقة يربط بين الـ endpoints والـ models والـ Mongo لإضافته كـ reference في مشروعك.

## 1) الراوتر `/process`

```python
@router.post("/process")
async def process_endpoint(project_id: str, file_id: str | None = None, request: Request):
    db = request.app.state.db
    assets_model = AssetModel(db)
    chunk_model = ChunkModel(db)

    # 1) تحديد قائمة الـ assets
    if file_id is not None:
        asset = await assets_model.get_by_name(project_id=project_id, name=file_id)
        if asset is None:
            return JSONResponse({"error": "file_id_error"}, status_code=400)
        assets = [asset]
    else:
        assets = await assets_model.get_by_project_id(project_id=project_id)
        if not assets:
            return JSONResponse({"error": "no_files_error"}, status_code=400)

    # 2) لوب على كل asset
    for asset in assets:
        file_path = asset.path
        if not os.path.exists(file_path):
            logger.error(f"File not found: {file_path}")
            continue

        content = get_file_content(file_path)
        if content is None:
            logger.error(f"Cannot read file: {file_path}")
            continue

        chunks = split_to_chunks(content)  # list[str]

        # 3) حفظ الـ chunks في Mongo
        for ch in chunks:
            await chunk_model.insert_chunk(
                project_id=project_id,
                asset_id=asset.id,
                text=ch,
                source=file_path,
            )

    return {"status": "ok"}
```


## 2) AssetModel (Mongo + Pydantic)

```python
class AssetModel:
    def __init__(self, db):
        self.collection = db["assets"]

    async def get_by_project_id(self, project_id: str, type_: str | None = None) -> list[Asset]:
        query = {"project_id": ObjectId(project_id)}
        if type_ is not None:
            query["type"] = type_
        docs = await self.collection.find(query).to_list(length=None)
        return [Asset(**doc) for doc in docs]

    async def get_by_name(self, project_id: str, name: str) -> Asset | None:
        doc = await self.collection.find_one(
            {"project_id": ObjectId(project_id), "name": name}
        )
        return Asset(**doc) if doc else None
```

### كود مبسط للـ endpoint

```python
@router.post("/process")
async def process_endpoint(
    request: Request,
    project_id: str,
    file_id: str | None = None,   # بقى اختياري
):
    db = request.app.state.db
    assets_model = AssetModel(db)
    chunks_model = ChunkModel(db)

    project_file_ids: list[tuple[ObjectId, str]] = []

    if file_id is not None:
        # سيناريو: مستخدم بعت اسم فايل واحد
        asset = await assets_model.get_by_name(project_id=project_id, name=file_id)
        if asset is None:
            return JSONResponse(
                {
                    "signal": "FILE_ID_ERROR",
                    "message": f"File {file_id} not found in assets",
                },
                status_code=400,
            )
        project_file_ids = [(asset.id, asset.name)]
    else:
        # سيناريو: مفيش file_id → هات كل فايلات المشروع
        assets = await assets_model.get_by_project_id(
            project_id=project_id,
            type_="file",
        )
        project_file_ids = [(a.id, a.name) for a in assets]

    # تأكيد إن فيه فايلات أصلًا
    if len(project_file_ids) == 0:
        return JSONResponse(
            {
                "signal": "NO_FILES_ERROR",
                "message": "No files found for this project",
            },
            status_code=400,
        )

    total_records = 0
    processed_files = 0

    for asset_id, file_name in project_file_ids:
        # هنا هيتم جلب المحتوى وعمل chunking وحفظه (هنيجي لها تحت)
        inserted = await process_single_file(
            chunks_model=chunks_model,
            project_id=project_id,
            asset_id=asset_id,
            file_name=file_name,
        )
        total_records += inserted
        processed_files += 1

    return {
        "signal": "OK",
        "files_processed": processed_files,
        "records_inserted": total_records,
    }
```

الفيديو ينبه إن التصميم ده موضع نقاش: ممكن تعمل endpoint منفصل لـ “process all” وآخر لـ “process single file”، أو توحّدهم زي ما هو عامل وتعتمد على optional param، حسب الـ API style اللي هتعتمده.[^4_1]

## فاليديشن لوجود الفايل على الـ filesystem

قبل التعديلات، `get_file_content` كانت بتفترض إن الفايل موجود بمجرد وجود path في الداتابيز.[^4_1]
الآن بقى في check صريح باستخدام `os.path.exists`، ولو الفايل مش موجود ترجع `None` والراوتر يتعامل مع الحالة دي بلوج.[^4_1]

### كود فاليديشن في file loader

```python
import os
from langchain_community.document_loaders import TextLoader, PyPDFLoader

def get_file_loader(file_path: str):
    ext = os.path.splitext(file_path)[^4_1].lower()

    # تأكد إن الفايل أصلًا موجود
    if not os.path.exists(file_path):
        return None

    if ext == ".txt":
        return TextLoader(file_path, encoding="utf-8")
    elif ext == ".pdf":
        return PyPDFLoader(file_path)
    # لاحقًا: أنواع أخرى
    return None


def get_file_content(file_path: str) -> list[str] | None:
    loader = get_file_loader(file_path)
    if loader is None:
        return None

    docs = loader.load()  # LangChain Documents
    return [d.page_content for d in docs]
```


### التعامل مع `None` في الراوتر + logging

```python
import logging

logger = logging.getLogger(__name__)

async def process_single_file(chunks_model, project_id, asset_id, file_name: str) -> int:
    file_path = build_file_path(file_name)  # حسب طريقتك في التخزين

    # لو الفايل مش موجود على الـ FS
    if not os.path.exists(file_path):
        logger.error(f"File not found on disk: {file_path}")
        return 0

    contents = get_file_content(file_path)
    if contents is None:
        logger.error(f"Error while loading file content: {file_path}")
        return 0

    chunks = split_to_chunks(contents)  # تقطيع المحتوى

    inserted = 0
    for ch in chunks:
        await chunks_model.insert_chunk(
            project_id=project_id,
            asset_id=asset_id,
            text=ch,
            source=file_path,
        )
        inserted += 1

    return inserted
```

## إضافة `chunk_asset_id` وربط الـ chunks بالـ asset

- دلوقتي تمت إضافة حقل `chunk_asset_id` من نوع `ObjectId` يشير إلى `_id` بتاع الـ asset في collection `assets`، عشان تقدر تسترجع chunks لكل فايل بسهولة وتعمل تحليل على مستوى الملف.[^4_1]

## إصلاحات الكوبي‑بيست و refactor داخل الـ loop

- كان فيه خطأ: `delete_by_project_id` كانت بتتندَه جوه الـ `for` اللي بيلف على الفايلات، فكل مرة تعالج فايل كانت بتحذف كل الشانكس القديمة ثم تضيف الجديدة، ففعليًا كان بيبقى فايل واحد بس في الآخر.[^4_1]
- التعديل: الـ delete يحصل مرة واحدة قبل الدخول في الـ loop على الفايلات، وبعدها تبدأ تضيف لكل فايل من غير ما تمسح تاني.[^4_1]

## ضبط الـ Models للرجوع بـ Pydantic بدل dict

## lifespan: تهيئة وغلق Mongo داخل FastAPI

```python
@asynccontextmanager
async def lifespan(app: FastAPI):
    client = AsyncIOMotorClient(MONGODB_URI)            # 1
    db = client[MONGODB_DB_NAME]                        # 2
    app.state.db_client = client                        # 3
    app.state.db = db                                   # 4
    try:
        yield                                           # 5
    finally:
        client.close()                                  # 6
```

- السطر 1: إنشاء `AsyncIOMotorClient` باستخدام الـ URI من الـ env؛ ده بيعمل connection pool للـ app.[^5_3]
- السطر 2: اختيار database بعينها من الـ Mongo client، زي `mini_rag`.[^5_3]
- السطر 3: تخزين الـ client في `app.state` عشان يبقى متاح من أي راوتر عبر `request.app.state.db_client`.[^5_3]
- السطر 4: تخزين object الـ db نفسه في `app.state.db` لتسهيل الوصول المباشر للداتابيز بدون إعادة بناء client.[^5_3]
- السطر 5: `yield` هنا بيقول لـ FastAPI “من هنا يبدأ تشغيل التطبيق”، وأي كود قبلها يعتبر startup logic.[^5_3]
- السطر 6: في نهاية حياة التطبيق (shutdown)، بيتم غلق Mongo client وتنظيف الموارد.[^5_3]

نقطة مهمة: استخدام lifespan pattern أفضل من events القديمة (`startup`/`shutdown`) في الإصدارات الحديثة من FastAPI.[^5_3]

## ملف `src/helpers/config.py`

هنا الطبقة اللي بتحوّل `.env` إلى object مضبوط typed تستخدمه في كل المشروع.[^7_1]

```python
from pydantic_settings import BaseSettings, SettingsConfigDict
```

- `BaseSettings`: كلاس من Pydantic v2 مصمم لإدارة configuration من env variables/files.[^7_1]
- `SettingsConfigDict`: طريقة حديثة في Pydantic v2 لتعريف إعدادات الـ Config بدل الكلاس الداخلي القديم.[^7_1]


### كلاس Settings

```python
class Settings(BaseSettings):
    APP_NAME: str
    APP_VERSION: str

    OPENAI_API_KEY: str

    FILE_ALLOWED_TYPES: list
    FILE_MAX_SIZE: int
    FILE_DEFAULT_CHUNK_SIZE: int

    MONGODB_URL: str
    MONGODB_DATABASE: str

    GENERATION_BACKEND: str
    EMBEDDING_BACKEND: str

    OPENAI_API_KEY: str = None
    OPENAI_API_URL: str = None
    COHERE_API_KEY: str = None

    GENERATION_MODEL_ID: str = None
    EMBEDDING_MODEL_ID: str = None
    EMBEDDING_MODEL_SIZE: int = None

    INPUT_DAFAULT_MAX_CHARACTERS: int = None
    GENERATION_DAFAULT_MAX_TOKENS: int = None
    GENERATION_DAFAULT_TEMPERATURE: float = None
```

شرح النقاط important:

- `class Settings(BaseSettings)`: أي attribute هنا بيتملأ أوتوماتيك من env vars اللي لها نفس الاسم (by default).[^7_1]
- `APP_NAME`, `APP_VERSION`: لازم يتوفروا (مفيش default)، وإلا Pydantic هيرفع error عند إنشاء Settings.[^7_1]
- `FILE_ALLOWED_TYPES: list`: هتتشال من env كـ string، وPydantic يحاول يحوّلها لـ list؛ غالبًا بيستخدم JSON-like syntax في `.env` (زي `["text/plain","application/pdf"]`).[^7_1]
- `MONGODB_URL`, `MONGODB_DATABASE`: نفس القيم اللي عرفتها في `.env.example`.[^7_1]

لاحظ: فيه تكرار لـ `OPENAI_API_KEY` مرة بدون default ومرة بـ `= None`؛ ده واضح إنه glitch بسيط في الفرع ده، وفي الفروع الأحدث بيتصلّح بتعريف واحد فقط.[^7_3][^7_1]

المجموعة الأخيرة:

- `GENERATION_MODEL_ID`, `EMBEDDING_MODEL_ID`, `EMBEDDING_MODEL_SIZE`: إعدادات الموديلات نفسها؛ قيمهم من `.env`.[^7_1]
- `INPUT_DAFAULT_MAX_CHARACTERS`, `GENERATION_DAFAULT_MAX_TOKENS`, `GENERATION_DAFAULT_TEMPERATURE`: نفس القيم اللي عرفتها في `.env.example`, لكن optional في الكود (default = None) عشان تقدر تحط defaults في أماكن أخرى لو حبيت.[^7_1]


### Config الداخلي (مصدر env)

```python
    class Config:
        env_file = ".env"
```

- بيقول لـ Pydantic إن مصدر الإعدادات ملف `.env` في root الـ project، بالإضافة إلى الـ env variables الموجودة في الـ system.[^7_1]
- ترتيب الأولوية: env vars في النظام > القيم الموجودة في `.env` > الـ defaults المكتوبة في الكلاس.[^7_1]

في Pydantic v2، الشكل الرسمي بقى:

```python
model_config = SettingsConfigDict(env_file=".env")
```

بدل class Config؛ لكن في الفرع ده لسه مستخدم style v1، وغالبًا هيتم تحديثه في فروع لاحقة.[^7_1]

### دالة get_settings

```python
def get_settings():
    return Settings()
```

- دي abstraction بسيطة عشان ما تنشئش `Settings()` كل مرة بإيدك في كل ملف.[^7_1]
- في `main.py` أو في أي راوتر هتستعملها كده:

```python
from helpers.config import get_settings

settings = get_settings()
print(settings.MONGODB_URL)
```

- Pydantic بيعمل internal caching عادةً (أو ممكن تضيف caching بنفسك) عشان ما يعيدش قراءة `.env` ألف مرة، لكن حتى لو ما فيش caching، حجم الإعدادات صغير جدًا.[^7_1]

- `get_settings`: يجيب object الإعدادات اللي شرحناه من `.env` (Mongo, LLM, files...).[^8_1]
- `LLMProviderFactory`: factory بترجع client مناسب حسب الـ backend (OpenAI, Cohere, ...).[^8_1]
- `app = FastAPI()`: إنشاء instance واحدة global يستخدمها Uvicorn/Docker.[^8_1]


## دالة startup_db_client

```python

    app.mongo_conn = AsyncIOMotorClient(settings.MONGODB_URL)
    app.db_client = app.mongo_conn[settings.MONGODB_DATABASE]
```

- `settings = get_settings()`:

- `app.mongo_conn = AsyncIOMotorClient(settings.MONGODB_URL)`:
    - ينشئ connection pool لـ Mongo باستخدام الـ URL اللي في الإعدادات (من `.env.example`: `MONGODB_URL`).[^8_1]

- `llm_provider_factory = LLMProviderFactory(settings)`:
    - ينشئ factory واحدة بتعرف من الإعدادات انت عايز تستخدم أي providers (OpenAI/Cohere...).[^8_1]

# اكمل

هكمل دلوقتي طبقة الـ LLM abstraction: الـ interface، الـ enums، والـ factory اللي بتوصلهم بالإعدادات اللي في `.env`.[^9_1]

## LLMInterface: عقد موحّد لكل مزوّد

```python
from abc import ABC, abstractmethod

class LLMInterface(ABC):

    @abstractmethod
    def set_generation_model(self, model_id: str):
        pass

    @abstractmethod
    def set_embedding_model(self, model_id: str, embedding_size: int):
        pass

    @abstractmethod
    def generate_text(self, prompt: str, chat_history: list = [], max_output_tokens: int = None, temperature: float = None):
        pass

    @abstractmethod
    def embed_text(self, text: str, document_type: str = None):
        pass

    @abstractmethod
    def construct_prompt(self, prompt: str, role: str):
        pass
```

سطر‑بسطر:

- `from abc import ABC, abstractmethod`: استيراد الـ base class للأصناف المجردة (abstract) والـ decorator `@abstractmethod`.[^9_1]
- `class LLMInterface(ABC)`:
    - تعريف interface مجرد (مافيهوش implementation حقيقي)، يجبر أي provider (OpenAI, Cohere, ... ) يطبّق نفس الـ contract.[^9_1]

الميثودز:

- `set_generation_model(self, model_id: str)`:
    - كل provider لازم يعرف يضبط موديل التوليد (مثلاً يختار `gpt-3.5-turbo-0125` أو موديل Cohere المناسب).[^9_1]
- `set_embedding_model(self, model_id: str, embedding_size: int)`:
    - نفس الفكرة لكن للـ embeddings، مع تمرير حجم الـ vector (384 مثلاً).[^9_2]
- `generate_text(...)`:
    - abstraction لـ call الجينيريشن. البراميترز:
        - `prompt`: النص الأساسي أو الـ system prompt.[^9_1]
        - `chat_history: list = []`: تاريخ المحادثة (قائمة رسائل) يختلف تمثيلها بين OpenAI/Cohere، لكن الـ interface يفرض عليك تقبّله.[^9_1]
        - `max_output_tokens`: سقف الـ tokens للرد.
        - `temperature`: درجة العشوائية في الرد.[^9_1]
- `embed_text(self, text: str, document_type: str = None)`:
    - abstraction لعمل embedding لنص واحد؛ `document_type` ممكن يكون `"document"` أو `"query"` (هتظهر في `DocumentTypeEnum`).[^9_1]
- `construct_prompt(self, prompt: str, role: str)`:
    - يبني الرسالة بالشكل المناسب للـ provider (OpenAI عنده roles `system/user/assistant`، Cohere له صياغة مختلفة).[^9_1]

الفكرة الأساسية:

- كل provider يطبق الـ interface ده، فتقدر تغيّر من OpenAI لـ Cohere أو العكس بدون ما تغير الراوترات؛ بس تغيّر backend في `.env`.[^9_1]

# نعمل endpoint كامل /ask/{project_id} فوق mini-RAG

هنبني endpoint `/ask/{project_id}` كطبقة رفيعة فوق اللي موجود في `tut-008`: ياخد سؤال، يجيب الشنكس من Mongo، يحوّلها لسياق، وينادي LLM abstraction للـ إجابة.[^14_1]

## شكل الـ endpoint المقترح

```python
from fastapi import APIRouter, Request
from pydantic import BaseModel
from models.chunk import ChunkModel

ask_router = APIRouter(prefix="/ask", tags=["ask"])


class AskRequest(BaseModel):
    question: str
    top_k: int = 5


class AskResponse(BaseModel):
    answer: str
    context_chunks: list[str]


@ask_router.post("/{project_id}", response_model=AskResponse)
async def ask_project(request: Request, project_id: str, body: AskRequest):
    db_client = request.app.db_client

    # 1) هات الشنكس الخاصة بالمشروع من Mongo
    chunk_model = await ChunkModel.create_instance(db_client=db_client)
    chunks = await chunk_model.get_chunks_by_project_id(
        project_id=project_id,
        limit=body.top_k,
    )

    if not chunks:
        return AskResponse(answer="لا توجد بيانات متاحة لهذا المشروع.", context_chunks=[])

    # 2) كوّن سياق نصي من الشنكس
    context_parts = [c.chunk_text for c in chunks]
    context_text = "\n\n".join(context_parts)

    # 3) ابني الـ prompt
    prompt = f"""أنت مساعد ذكي يجيب عن الأسئلة بناءً على السياق التالي فقط.

السياق:
{context_text}

السؤال:
{body.question}

الإجابة بالعربية وبشكل واضح ومختصر، ولو المعلومة غير موجودة في السياق قل إنك لا تعرف ولا تخترع إجابة.
"""

    # 4) نادِي LLM abstraction
    generation_client = request.app.generation_client
    answer = generation_client.generate_text(
        prompt=prompt,
        chat_history=[],
        max_output_tokens=512,
        temperature=0.1,
    )

    if not answer:
        answer = "حدث خطأ أثناء توليد الإجابة."

    return AskResponse(
        answer=answer,
        context_chunks=context_parts,
    )
```

## الفكرة المعمارية العامة

- الهدف: تفصل مشروعك عن مزود LLM معين (OpenAI، Cohere، Ollama...) عن طريق واجهة موحدة (Interface) وFactory.[^16_1]
- الـ LLM مسؤول عن مهمتين أساسيتين:
    - **Embedding**: تحويل النصوص إلى vectors للتخزين في vector DB.
    - **Generation**: توليد إجابات نصية من الـ context + السؤال.[^16_1]


## LLMInterface (الانترفيس)

الكود (مكافئ لما في الريبو `LLMInterface.py`):[^16_2]

```python
from abc import ABC, abstractmethod

class LLMInterface(ABC):

    @abstractmethod
    def set_generation_model(self, model_id: str):
        pass

    @abstractmethod
    def set_embedding_model(self, model_id: str, embedding_size: int):
        pass

    @abstractmethod
    def generate_text(
        self,
        prompt: str,
        chat_history: list = [],
        max_output_tokens: int = None,
        temperature: float = None,
    ):
        pass

    @abstractmethod
    def embed_text(self, text: str, document_type: str = None):
        pass

    @abstractmethod
    def construct_prompt(self, prompt: str, role: str):
        pass
```

- يرث من `ABC` عشان يبقى interface حقيقي.[^16_2]
- `set_generation_model` / `set_embedding_model`: لضبط الموديل IDs والـ embedding size في runtime بدل تثبيتهم في `__init__`.[^16_1]
- `generate_text`: abstraction فوق الـ chat/generation API لأي provider (OpenAI/Cohere/غيرهم).[^16_2]
- `embed_text`: abstraction فوق API الـ embeddings، مع `document_type` (document أو query).[^16_1]
- `construct_prompt`: توحيد الشكل الداخلي للرسالة حسب الـ provider (OpenAI: role/content، Cohere: role/text).[^16_2]

## LLMProviderFactory (الفاكتوري)

الكود (من `LLMProviderFactory.py`):[^16_2]

```python
from .LLMEnums import LLMEnums
from .providers.OpenAIProvider import OpenAIProvider
from .providers.CoHereProvider import CoHereProvider


class LLMProviderFactory:
    def __init__(self, config):
        self.config = config

    def create(self, provider: str):
        if provider == LLMEnums.OPENAI.value:
            return OpenAIProvider(
                api_key=self.config.OPENAI_API_KEY,
                api_url=self.config.OPENAI_API_URL,
                default_input_max_characters=self.config.INPUT_DAFAULT_MAX_CHARACTERS,
                default_generation_max_output_tokens=self.config.GENERATION_DAFAULT_MAX_TOKENS,
                default_generation_temperature=self.config.GENERATION_DAFAULT_TEMPERATURE,
            )

        if provider == LLMEnums.COHERE.value:
            return CoHereProvider(
                api_key=self.config.COHERE_API_KEY,
                default_input_max_characters=self.config.INPUT_DAFAULT_MAX_CHARACTERS,
                default_generation_max_output_tokens=self.config.GENERATION_DAFAULT_MAX_TOKENS,
                default_generation_temperature=self.config.GENERATION_DAFAULT_TEMPERATURE,
            )

        return None
```

- يأخذ `settings` (من `get_settings()` في `helpers/config.py`) كـ config.[^16_2]
- `create("OPENAI")`: يرجّع `OpenAIProvider` مضبوط بكل القيم من `.env` (limits, temperature...).[^16_2]
- `create("COHERE")`: يرجّع `CoHereProvider` بنفس الـ interface.[^16_2]
- باقي الكود (main.py) يستعمله في startup لإنشاء:
    - `app.generation_client`
    - `app.embedding_client`
ويضبط الموديلات من `GENERATION_MODEL_ID` و `EMBEDDING_MODEL_ID`.[^16_2]

المحاضرة دي بتكمّل بناء طبقة **LLM abstraction** في mini‑RAG: بتصمّم Interface، Providers لـ OpenAI وCohere، Factory، وبتربطهم في FastAPI Lifespan بحيث تقدر تبدّل الـ backend من الكونفيج بس بدون لمس بقية الكود.[^18_1][^18_2]

## 1) الفكرة المعمارية والقرارات الأساسية

- النظام محتاج مزوّد واحد (أو أكثر) يقوم بـ:
    - **Embedding**: تحويل الشنكس لنقاط (vectors) عشان تتخزن في Vector DB وتستخدم في البحث الدلالي.[^18_1]
    - **Generation**: توليد إجابات بناءً على السياق (chunks المسترجعة) + سؤال المستخدم.[^18_1]
- القرار المعماري:
    - عدم ربط المشروع بـ OpenAI فقط؛ لازم يبقى سهل تبدّل لـ Cohere أو Ollama أو أي provider تاني بدون إعادة كتابة الراوترات أو الـ pipeline.[^18_1]
    - الحل:
        - واجهة موحّدة `LLMInterface` تُفرض على جميع الـ providers.
        - Factory `LLMProviderFactory` تتولى اختيار وإنشاء الـ provider المناسب من الكونفيج.[^18_2]

**تحسين محتمل**: من أول يوم تعرّف Enum لـ backends (إلزاميًا)، وتمنع الاستخدام الحر للـ strings عشان تقلل الأخطاء في الكونفيج.[^18_2]

## 2) تصميم LLMInterface خطوة بخطوة

ملف `src/stores/llm/LLMInterface.py`:[^18_2]

```python
from abc import ABC, abstractmethod

class LLMInterface(ABC):

    @abstractmethod
    def set_generation_model(self, model_id: str):
        pass
```

- `ABC`: يعلن أن الكلاس مجرد **واجهة** (abstract base class).
- `set_generation_model`: قرار مهم إن إعداد الـ model ما يبقاش في `__init__` فقط، بل في دالة setter، عشان تقدر تغيّره **في runtime** (job معيّنة تستخدم model مختلف).[^18_1]

```python
    @abstractmethod
    def set_embedding_model(self, model_id: str, embedding_size: int):
        pass
```

- لازم أي provider يدعم:
    - `embedding_model_id`.
    - `embedding_size` (عدد الأبعاد)؛ مهم لاحقًا لـ Vector DB (pgvector/Qdrant) اللي بتطلب الـ dimension وقت إنشاء الجدول/collection.[^18_3]

```python
    @abstractmethod
    def generate_text(
        self,
        prompt: str,
        chat_history: list = [],
        max_output_tokens: int = None,
        temperature: float = None,
    ):
        pass
```

- abstraction موحّد للتوليد:
    - `prompt`: نص السؤال/الـ instruction.
    - `chat_history`: هيستوري الرسائل (system/user/assistant) اللي هتتنفذ حسب الـ provider.[^18_2]
    - `max_output_tokens` + `temperature`: ممكن تتضبط per-call أو يعتمد على defaults من الكونفيج.[^18_1]

```python
    @abstractmethod
    def embed_text(self, text: str, document_type: str = None):
        pass
```

- abstraction للـ embeddings:
    - `document_type`: هل النص **document** ولا **query**؛ بعض الـ providers (Cohere مثلاً) يغيروا الـ behaviour حسب النوع (`search_document` vs `search_query`).[^18_2]

```python
    @abstractmethod
    def construct_prompt(self, prompt: str, role: str):
        pass
```

- توحيد طريقة بناء message حسب الـ provider:
    - OpenAI: `{ "role": "user", "content": "..." }`.
    - Cohere: `{ "role": "USER", "text": "..." }`.[^18_2]

**تحسين محتمل**:

- تغيير default argument لـ `chat_history: list = []` إلى `chat_history: Optional[list] = None` لتجنّب mutable default argument bug (كود سميل في بايثون).[^18_2]

## 7) FastAPI Lifespan: ربط Mongo + LLM

في `src/main.py` في `tut-008` تم الانتقال من `@app.on_event("startup")` إلى **lifespan** pattern (أو في نسخة أخرى: `app.router.lifespan.on_startup`) لتفادي deprecation warnings في FastAPI.[^18_2]

- في startup:
    - إنشاء `AsyncIOMotorClient` وربط `app.db_client`.
    - إنشاء `LLMProviderFactory(settings)`.
    - إنشاء `app.generation_client` و `app.embedding_client` وضبط الموديلات.[^18_2]
- في shutdown:
    - إغلاق Mongo client وتنظيف الموارد.[^18_2]

**قرار تصميم مهم**:

- حفظ الـ clients في `app` (أو `app.state`) حتى تصبح متاحة لكل الراوترات بدون إنشاء client جديد لكل request، مما يحافظ على الأداء ويمنع leaks.[^18_2]

## كيف تحسّن/تطوّر هذا التصميم في مشروعك؟

بناءً على المحاضرة والكود:[^18_1][^18_2]

- استخدم:

لو تحب، يمكن في الرسالة التالية كتابة نسخة مُحسّنة بالكامل لطبقة LLM دي (interface + providers + factory + settings) tailored لمشروع الـ RAG الخاص بتفريغ وترجمة الملفات عندك، مع مراعاة Pydantic v2 وOllama كـ backend ثالث.

# ازاي احسن الكود مع الشرح المفصل لكل قرار

أفضل تحسين إنك تتعامل معها كـ **LLM layer v2** مبنية على نفس الفكرة لكن أنضف، أقوى typing، وأقل surprises في الإنتاج. هقسم لك التحسينات كمحاور، ومع كل واحدة: الكود + ليه القرار ده مهم.[^19_1]

***

## 1) تصليح الـ Interface (mutable defaults + typing)

### المشكلة 1: `chat_history: list = []` (mutable default)

```python
# الحالي
def generate_text(self, prompt: str, chat_history: list = [], ...):
    ...
```

- في بايثون، الـ list اللي في الـ default بتتشارك بين كل الاستدعاءات، وده ممكن يعمل bugs غريبة (الهستوري بتاع ريكويست يدخل في ريكويست تاني).[^19_1]


### التحسين

```python
from typing import List, Dict, Optional, Protocol

class LLMInterface(Protocol):
    def set_generation_model(self, model_id: str) -> None: ...
    def set_embedding_model(self, model_id: str, embedding_size: int) -> None: ...

    def generate_text(
        self,
        prompt: str,
        chat_history: Optional[List[Dict]] = None,
        max_output_tokens: Optional[int] = None,
        temperature: Optional[float] = None,
    ) -> str: ...

    def embed_text(
        self,
        text: str,
        document_type: Optional[str] = None,
    ) -> List[float]: ...

    def construct_prompt(self, prompt: str, role: str) -> Dict: ...
```

**قرارات:**

- استخدام `Protocol` بدل `ABC` يسهل duck typing، وسهل في الـ tests وحتى لو backend مش موروث فعليًا.[^19_1]
- `Optional[List[Dict]] = None` بدل `[]` لتجنّب mutable defaults.
- إضافة return types (`-> str`, `-> List[float]`) يسهّل جدًا اكتشاف الأخطاء في IDE والـ mypy.[^19_1]

## 3) توحيد BaseProvider وتخفيف التكرار

OpenAI وCohere عندهم نفس البنية تقريبًا (defaults, process_text, logging, validation). بدل تكرار، نعمل Base class.

### BaseLLMProvider

```python
from typing import Optional, List
import logging

class BaseLLMProvider:
    def __init__(
        self,
        default_input_max_characters: int,
        default_generation_max_output_tokens: int,
        default_generation_temperature: float,
    ) -> None:
        self.default_input_max_characters = default_input_max_characters
        self.default_generation_max_output_tokens = default_generation_max_output_tokens
        self.default_generation_temperature = default_generation_temperature

        self.generation_model_id: Optional[str] = None
        self.embedding_model_id: Optional[str] = None
        self.embedding_size: Optional[int] = None

        self.logger = logging.getLogger(self.__class__.__name__)

    def process_text(self, text: str) -> str:
        return text[: self.default_input_max_characters].strip()

    def ensure_generation_ready(self) -> bool:
        if not self.generation_model_id:
            self.logger.error("Generation model is not set")
            return False
        return True

    def ensure_embedding_ready(self) -> bool:
        if not self.embedding_model_id:
            self.logger.error("Embedding model is not set")
            return False
        return True
```

**قرارات:**

- نقل logic المشترك (limits + validation + logging) في base class يقلل احتمال التناقض بين OpenAI/Cohere.[^19_1]
- `logger` باسم الكلاس نفسه يسهل قراءته في الملفات logs.[^19_1]

## 4) تحسين LLMProviderFactory (no `None`, typing أوضح)

### المشكلة 3: factory ممكن ترجع None

```python
# الحالي
def create(self, provider: str):
    if provider == LLMEnums.OPENAI.value: ...
    if provider == LLMEnums.COHERE.value: ...
    return None
```

ده يسمح إن الكود في `main.py` يمشي بدون ما ياخد باله إن رجع None، ويتكسر بعيد عن مكان المشكلة.

### التحسين

```python
from typing import Final

class LLMProviderFactory:
    def __init__(self, settings: Settings) -> None:
        self.settings = settings

    def create(self, provider: BackendEnum) -> LLMInterface:
        if provider is BackendEnum.OPENAI:
            if not self.settings.OPENAI_API_KEY:
                raise ValueError("OPENAI_API_KEY is required for OPENAI backend")
            return OpenAIProvider(
                api_key=self.settings.OPENAI_API_KEY,
                api_url=self.settings.OPENAI_API_URL,
                settings=self.settings,
            )

        if provider is BackendEnum.COHERE:
            if not self.settings.COHERE_API_KEY:
                raise ValueError("COHERE_API_KEY is required for COHERE backend")
            return CoHereProvider(
                api_key=self.settings.COHERE_API_KEY,
                settings=self.settings,
            )

        # backend مش مدعوم
        raise ValueError(f"Unsupported LLM backend: {provider}")
```

**قرارات:**

- factory **لا تعيد None** مطلقًا؛ لو backend غير مدعوم → استثناء واضح في startup، أحسن من crash غريب بعد ساعة.[^19_1]
- يتحقق من وجود API key قبل إنشاء provider، وإلا يرمي error مبكرًا.[^19_1]

```python
from typing import Optional

from helpers.settings import Settings


class BaseLLMProvider:
    def __init__(self, settings: Settings) -> None:
        self.default_input_max_characters = settings.INPUT_DEFAULT_MAX_CHARACTERS
        self.default_generation_max_output_tokens = settings.GENERATION_DEFAULT_MAX_TOKENS

        self.embedding_model_id: Optional[str] = None
        self.embedding_size: Optional[int] = None

        return True

    def ensure_embedding_ready(self) -> bool:
        if not self.embedding_model_id:
```

## 1) Retry بسيط مع Backoff

### أ) Utility عام للـ retry

```python
# src/stores/llm/utils.py
import asyncio
import random
from typing import Callable, TypeVar, Awaitable

T = TypeVar("T")


async def async_retry_with_backoff(
    func: Callable[[], Awaitable[T]],
    retries: int = 3,
    base_delay: float = 0.5,
    max_delay: float = 5.0,
) -> T | None:
    """
    ينفّذ func مع retry بسيط و exponential backoff.
    - retries: عدد المحاولات بعد الأولى.
    - base_delay: التأخير الأساسي.
    - max_delay: أقصى تأخير بين المحاولات.
    """
    attempt = 0

    while True:
        try:
            return await func()
        except Exception as e:
            attempt += 1
            if attempt > retries:
                # بعد آخر محاولة: لا retry، نرجّع None
                return None

            # backoff: delay = base * 2^(attempt-1) + jitter بسيط
            delay = min(base_delay * (2 ** (attempt - 1)), max_delay)
            delay = delay * (0.8 + 0.4 * random.random())
            await asyncio.sleep(delay)
```

**الشرح:**

- `func: Callable[[], Awaitable[T]]`:
    - بناخد دالة async بدون بارامترات (هنغلّف call الحقيقي داخل lambda).[^21_1]
- `retries`: عدد المحاولات الإضافية (لو 3 → المجموع 4 محاولات: الأصلية + 3).[^21_1]
- `while True`:
    - يحاول ينفّذ `func()`؛ لو نجحت → يرجّع القيمة.[^21_1]
- لو حصل استثناء:
    - يزيد `attempt`.
    - لو تعدّى `retries` → يرجّع `None` (فشل نهائي بدون crash).[^21_1]
    - يحسب `delay`:
        - `base * 2^(attempt-1)` = exponential backoff.
        - `min(..., max_delay)` = سقف أقصى.
        - jitter بسيط لتجنب thundering herd (الكل يحاول في نفس اللحظة).[^21_1]
- `await asyncio.sleep(delay)` يوقف الكوروتين الحالي فقط، مش event loop كله.[^21_1]


### ب) استخدامه في OpenAIProvider.generate_text

نفترض إنك عدّلت Provider ليكون async. (لو لسه sync هتحتاج wrapper عبر `anyio.to_thread.run_sync`، بس هنمشي async هنا لأنها أفضل مع FastAPI.)

```python
# داخل OpenAIProvider
from .utils import async_retry_with_backoff

    async def generate_text(
        self,
        prompt: str,
        chat_history: Optional[List[Dict]] = None,
        max_output_tokens: Optional[int] = None,
        temperature: Optional[float] = None,
    ) -> Optional[str]:
        if not self.ensure_generation_ready():
            return None

        chat_history = chat_history or []
        chat_history.append(
            self.construct_prompt(prompt=prompt, role=OpenAIEnums.USER.value)
        )

        max_tokens = max_output_tokens or self.default_generation_max_output_tokens
        temp = temperature or self.default_generation_temperature

        async def _call() -> Optional[str]:
            try:
                response = await self.client.chat.completions.create(
                    model=self.generation_model_id,
                    messages=chat_history,
                    max_tokens=max_tokens,
                    temperature=temp,
                )
            except Exception as e:
                self.logger.exception("OpenAI generate_text error: %s", e)
                raise

            if not response or not response.choices:
                self.logger.error("OpenAI returned no choices")
                return None

            message = response.choices[^21_0].message
            content = message.get("content") if isinstance(message, dict) else getattr(
                message, "content", None
            )
            if not content:
                self.logger.error("OpenAI response had empty content")
                return None

            return content

        return await async_retry_with_backoff(_call, retries=3, base_delay=0.5, max_delay=4.0)
```

**الشرح سطرًا سطرًا:**

- `async def generate_text(...):`:
    - تخلّي provider متوافق مع FastAPI async (أفضل لعدم حجز thread).[^21_1]
- `chat_history = chat_history or []`:
    - يعالج حالة `None` بدون مشاركة state بين الريكوستات.[^21_1]
- نبني `_call` كـ inner async function:
    - عشان نمرّرها لـ `async_retry_with_backoff` بعد التغليف.[^21_1]
- داخل `_call`:
    - `await self.client.chat.completions.create(...)`:
        - call الفعلي للـ API.[^21_1]
    - الاستثناءات:
        - نسجّلها بـ `logger.exception` ثم `raise` عشان الـ retry wrapper يلتقطها ويقرر يعيد المحاولة.[^21_1]
    - فاليديشن response:
        - نفس المنطق السابق، رجع `None` لو مفيش choices أو content.[^21_1]
- في الآخر:
    - `await async_retry_with_backoff(_call, ...)`
        - ينفّذ `_call`، ولو فشل بسبب exceptions يعيد المحاولة مع backoff.[^21_1]

نفس الفكرة تطبق في `embed_text` وCohereProvider.

## 2) قياس tokens بدل characters (tiktoken)

### أ) Utility لحساب tokens وتقطيع النص

```python
# src/stores/llm/token_utils.py
from typing import Tuple
import tiktoken


def count_tokens(text: str, model_name: str = "gpt-3.5-turbo-0125") -> int:
    """
    يحسب عدد التوكنز التقريبي للنص بناءً على موديل OpenAI.
    """
    enc = tiktoken.encoding_for_model(model_name)
    return len(enc.encode(text))


def truncate_to_token_limit(
    text: str,
    max_tokens: int,
    model_name: str = "gpt-3.5-turbo-0125",
) -> Tuple[str, int]:
    """
    يقطع النص بحيث لا يتجاوز max_tokens تقريبًا، ويرجع:
    - النص المقطوع
    - عدد التوكنز الفعلي بعد القطع
    """
    enc = tiktoken.encoding_for_model(model_name)
    tokens = enc.encode(text)

    if len(tokens) <= max_tokens:
        return text, len(tokens)

    truncated_tokens = tokens[:max_tokens]
    truncated_text = enc.decode(truncated_tokens)
    return truncated_text, len(truncated_tokens)
```

**القرارات:**

- `encoding_for_model(model_name)`:
    - تستخدم encoding المناسب للموديل عشان تكون التقديرات أقرب للحقيقة.[^21_2]
- `truncate_to_token_limit`:
    - بدل قصّ النص على عدد حروف (غير دقيق) → قص بناءً على tokens الفعليين.[^21_2]

### Provider (مقتطف بسيط)

```python
# src/stores/llm/providers/OllamaProvider.py
import httpx
from typing import Optional, List
from .base import BaseLLMProvider
from ..interfaces import TextEmbedderInterface
from ..LLMEnums import DocumentTypeEnum
from helpers.settings import Settings


class OllamaProvider(BaseLLMProvider, TextEmbedderInterface):
    def __init__(self, settings: Settings) -> None:
        super().__init__(settings)
        self.base_url = settings.OLLAMA_BASE_URL
        self.model_id = settings.OLLAMA_EMBED_MODEL
        self.client = httpx.AsyncClient(base_url=self.base_url, timeout=30)

    def set_embedding_model(self, model_id: str, embedding_size: int) -> None:
        self.model_id = model_id
        self.embedding_size = embedding_size

    async def embed_text(
        self,
        text: str,
        document_type: Optional[DocumentTypeEnum] = None,
    ) -> Optional[List[float]]:
        processed = self.process_text(text)

        payload = {
            "model": self.model_id,
            "input": processed,
        }

        try:
            resp = await self.client.post("/api/embeddings", json=payload)
            resp.raise_for_status()
        except Exception as e:
            self.logger.exception("Ollama embed_text failed: %s", e)
            return None

        data = resp.json()
        embedding = data.get("embedding")
        if not embedding:
            self.logger.error("Ollama returned empty embedding")
            return None

        return embedding
```

**القرارات:**

- استخدام `httpx.AsyncClient` متوافق مع FastAPI، أفضل من `requests` في بيئة async.[^23_1]
- provider متخصص في embeddings فقط، generation يبقى عند OpenAI/Cohere.

ثم في Factory:

```python

class LLMProviderFactory:
    ...
    def create_embedder(self, provider: BackendEnum) -> TextEmbedderInterface:

            return OllamaProvider(self.settings)
        ...
```

```python
class RequestIDMiddleware(BaseHTTPMiddleware):

        response = await call_next(request)
        response.headers["X-Request-ID"] = request_id
```

## 3) OllamaProvider للـ embeddings

### شكل API لـ Ollama

من الدوكيومنت:[^24_1][^24_2]

- الرد يحتوي `embeddings` أو `embedding` حسب النسخة.[^24_3][^24_2]


### الكود

```python
# src/stores/llm/providers/OllamaProvider.py
from typing import Optional, List
import httpx

from .base import BaseLLMProvider
from ..interfaces import TextEmbedderInterface
from ..LLMEnums import DocumentTypeEnum
from helpers.settings import Settings


class OllamaProvider(BaseLLMProvider, TextEmbedderInterface):
    """
    Provider مسؤول عن embeddings فقط باستخدام Ollama.
    """

    def __init__(self, settings: Settings) -> None:
        super().__init__(settings=settings)

        if not settings.OLLAMA_BASE_URL:
            raise ValueError("OLLAMA_BASE_URL is required for OllamaProvider")
        if not settings.OLLAMA_EMBED_MODEL:
            raise ValueError("OLLAMA_EMBED_MODEL is required for OllamaProvider")
        if not settings.OLLAMA_EMBEDDING_SIZE:
            raise ValueError("OLLAMA_EMBEDDING_SIZE is required for OllamaProvider")

        self.base_url = settings.OLLAMA_BASE_URL.rstrip("/")
        self.embedding_model_id = settings.OLLAMA_EMBED_MODEL
        self.embedding_size = settings.OLLAMA_EMBEDDING_SIZE

        # client HTTP async
        self.client = httpx.AsyncClient(
            base_url=self.base_url,
            timeout=30,
        )

    def set_embedding_model(self, model_id: str, embedding_size: int) -> None:
        """
        تقدر تغيّر موديل Ollama + حجم الـ embedding في runtime لو حبيت.
        """
        self.embedding_model_id = model_id
        self.embedding_size = embedding_size

    async def embed_text(
        self,
        text: str,
        document_type: Optional[DocumentTypeEnum] = None,
    ) -> Optional[List[float]]:
        """
        يحوّل نص واحد إلى vector باستخدام Ollama /api/embed.
        """
        if not self.embedding_model_id:
            self.logger.error("Ollama embedding model id is not set")
            return None

        processed = self.process_text(text)

        payload = {
            "model": self.embedding_model_id,
            "input": [processed],  # API تدعم batch؛ هنا نستخدم عنصر واحد
        }

        try:
            resp = await self.client.post("/api/embed", json=payload)
            resp.raise_for_status()
        except Exception as e:
            self.logger.exception("Ollama embed_text HTTP error: %s", e)
            return None

        try:
            data = resp.json()
        except Exception as e:
            self.logger.exception("Ollama embed_text JSON decode error: %s", e)
            return None

        # حسب الإصدار، ممكن يكون 'embeddings' أو 'embedding'
        embeddings = data.get("embeddings") or data.get("embedding")
        if not embeddings:
            self.logger.error("Ollama returned no embeddings: %s", data)
            return None

        # لو input واحد، نبقى متوقعين vector واحد
        first = embeddings[^24_0] if isinstance(embeddings[^24_0], list) else embeddings
        if not isinstance(first, list):
            self.logger.error("Ollama embedding format unexpected: %s", type(first))
            return None

        # Optional: تحقق من طول الـ vector
        if self.embedding_size and len(first) != self.embedding_size:
            self.logger.warning(
                "Ollama embedding size (%d) != expected (%d)",
                len(first),
                self.embedding_size,
            )

        return first
```

**قرارات:**

- `AsyncClient` من httpx متوافق مع FastAPI async ويستفيد من connection pooling.[^24_4]
- `payload["input"]` قائمة من نصوص، حتى لو عنصر واحد، متماشية مع docs.[^24_1][^24_2]
- مرونة في التعامل مع `embeddings` vs `embedding` بسبب اختلاف الإصدارات.[^24_3]

```python
from helpers.settings import Settings, BackendEnum
from .interfaces import TextGeneratorInterface, TextEmbedderInterface
from .providers.OpenAIProvider import OpenAIProvider
from .providers.CoHereProvider import CoHereProvider
from .providers.OllamaProvider import OllamaProvider


class LLMProviderFactory:
    def __init__(self, settings: Settings) -> None:
        self.settings = settings

    def create_generator(self, provider: BackendEnum) -> TextGeneratorInterface:
        if provider is BackendEnum.OPENAI:
            return OpenAIProvider(settings=self.settings)
        if provider is BackendEnum.COHERE:
            # لو حابب Cohere generation
            return CoHereProvider(settings=self.settings)
        raise ValueError(f"Unsupported generation backend: {provider}")

    def create_embedder(self, provider: BackendEnum) -> TextEmbedderInterface:
        if provider is BackendEnum.OPENAI:
            return OpenAIProvider(settings=self.settings)
        if provider is BackendEnum.COHERE:
            return CoHereProvider(settings=self.settings)
        if provider is BackendEnum.OLLAMA:
            return OllamaProvider(settings=self.settings)
        raise ValueError(f"Unsupported embedding backend: {provider}")
```

## 5) تحديث Lifespan في FastAPI

```python
# src/main.py
from fastapi import FastAPI
from contextlib import asynccontextmanager
from motor.motor_asyncio import AsyncIOMotorClient

from helpers.settings import get_settings
from stores.llm.LLMProviderFactory import LLMProviderFactory

settings = get_settings()

@asynccontextmanager
async def lifespan(app: FastAPI):
    mongo_client = AsyncIOMotorClient(settings.MONGODB_URL)
    db = mongo_client[settings.MONGODB_DATABASE]
    app.state.db_client = db

    factory = LLMProviderFactory(settings=settings)

    # Generation client (OpenAI/Cohere)
    generation_client = factory.create_generator(settings.GENERATION_BACKEND)
    generation_client.set_generation_model(settings.GENERATION_MODEL_ID)

    # Embedding client (Ollama مثلاً)
    embedding_client = factory.create_embedder(settings.EMBEDDING_BACKEND)
    embedding_client.set_embedding_model(
        model_id=settings.EMBEDDING_MODEL_ID,
        embedding_size=settings.EMBEDDING_MODEL_SIZE,
    )

    app.state.generation_client = generation_client
    app.state.embedding_client = embedding_client

    try:
        yield
    finally:
        await factory_close_clients(factory)  # لو حابب تنظّم غلق httpx client
        mongo_client.close()
```

```python
# src/stores/llm/errors.py

class LLMError(Exception):
    """
    خطأ عام في طبقة الـ LLM.
    ممكن تستخدمه كبِيس لكل الأخطاء المتخصصة.
    """
    pass


class LLMConfigError(LLMError):
    """
    خطأ في الكونفيج:
    - API key مفقود
    - model_id غير متضبط
    - backend غير مدعوم لهذا النوع من العملية
    """
    pass


class LLMProviderError(LLMError):
    """
    خطأ ناتج من مزوّد الخدمة:
    - network error
    - timeout / rate limit
    - response غير متوقع
    """
    pass
```

**قرارات:**

- كل الاستثناءات ترث من `LLMError` عشان تقدر تمسك كل أخطاء LLM في handler واحد لو حبيت.[^25_1]
- فصل `ConfigError` عن `ProviderError`:
    - Config → خطأ من جانبك (تضبيط).
    - Provider → خطأ من مزوّد خارجي أو الشبكة.

## 2) استخدام الاستثناءات داخل الـ Providers

### مثال في `OpenAIProvider` (generation)

```python
# src/stores/llm/providers/OpenAIProvider.py
from ..errors import LLMConfigError, LLMProviderError

    async def generate_text(...):
        if not self.ensure_generation_ready():
            self.logger.error("OpenAI generation model is not set")
            raise LLMConfigError("OpenAI generation model is not set")

        chat_history = chat_history or []
        chat_history.append(
            self.construct_prompt(prompt=prompt, role=OpenAIEnums.USER.value)
        )

        max_tokens = max_output_tokens or self.default_generation_max_output_tokens
        temp = temperature or self.default_generation_temperature

        async def _call() -> Optional[str]:
            try:
                response = await self.client.chat.completions.create(
                    model=self.generation_model_id,
                    messages=chat_history,
                    max_tokens=max_tokens,
                    temperature=temp,
                )
            except Exception as e:
                self.logger.exception("OpenAI generate_text error: %s", e)
                # أي خطأ في الاتصال بالمزوّد → ProviderError
                raise LLMProviderError(f"OpenAI generate_text failed: {e}") from e

            if not response or not response.choices:
                self.logger.error("OpenAI returned no choices")
                raise LLMProviderError("OpenAI returned empty choices")

            message = response.choices[^25_0].message
            content = message.get("content") if isinstance(message, dict) else getattr(
                message, "content", None
            )
            if not content:
                self.logger.error("OpenAI response had empty content")
                raise LLMProviderError("OpenAI returned empty content")

            return content

        # لو async_retry_with_backoff موجود:
        return await async_retry_with_backoff(_call, retries=3, base_delay=0.5, max_delay=4.0)
```

**النقاط المهمة:**

- في حالة config ناقص (model مش متضبط) → `LLMConfigError` مباشرة.
- في حالة network/API errors أو response غريب → `LLMProviderError`.
- ما بقاش فيه `return None` صامت في الحالات الحرجة؛ بدلاً من ذلك استثناء واضح.

نفس المنطق يتكرر في:

- `embed_text` داخل OpenAIProvider.
- CohereProvider / OllamaProvider.

## 3) Central error handling في FastAPI (global handler)

بدل ما تعالج هذه الأخطاء في كل endpoint يدويًا، تضيف **exception handlers** عامة.

### في `main.py` أو ملف `errors_handlers.py`

```python
# src/api/error_handlers.py
from fastapi import FastAPI, Request
from fastapi.responses import JSONResponse
from stores.llm.errors import LLMError, LLMConfigError, LLMProviderError


def register_error_handlers(app: FastAPI) -> None:
    @app.exception_handler(LLMConfigError)
    async def llm_config_error_handler(request: Request, exc: LLMConfigError):
        # خطأ من جانب السيرفر (config غلط) → 500
        return JSONResponse(
            status_code=500,
            content={
                "signal": "LLM_CONFIG_ERROR",
                "message": "There is a configuration error in the LLM service. Please contact the admin.",
                "details": str(exc),
            },
        )

    @app.exception_handler(LLMProviderError)
    async def llm_provider_error_handler(request: Request, exc: LLMProviderError):
        # خطأ من مزوّد خارجي → 502 (Bad Gateway) أو 503
        return JSONResponse(
            status_code=502,
            content={
                "signal": "LLM_PROVIDER_ERROR",
                "message": "LLM provider is temporarily unavailable or returned an invalid response.",
                "details": str(exc),
            },
        )

    @app.exception_handler(LLMError)
    async def llm_generic_error_handler(request: Request, exc: LLMError):
        # fallback لأي خطأ LLM آخر
        return JSONResponse(
            status_code=500,
            content={
                "signal": "LLM_ERROR",
                "message": "Unexpected LLM error occurred.",
                "details": str(exc),
            },
        )
```

ثم في `main.py`:

```python
from api.error_handlers import register_error_handlers

app = FastAPI(...)

register_error_handlers(app)
```

**النتيجة:**

- أي استثناء من نوع `LLMConfigError` أو `LLMProviderError` في أي مكان (router, service) سيوصل للمستخدم استجابة JSON موحدة ونظيفة.
- لا تحتاج try/except في كل endpoint لهذه الأنواع؛ يكفي ترك الاستثناء يطلع للـ handler المركزي.

## 4) ربط error handlers مع metrics (اختياري لكن قوي)

## ملخص الفوائد العملية

بإضافة Custom Exceptions + Central Error Handlers:

- **الكود أوضح**:
    - Providers يعبّروا عن نوع المشكلة بوضوح (`Config` vs `Provider`).
    - الراوترات نظيفة، بدون try/except مكرر لكل LLM call.
- **الـ API ثابتة**:

- **المراقبة أسهل**:
    - تقدر تربط Prometheus counters / logs بالـ error types، وتعرف هل المشكلة من إعداداتك أو من مزوّد خارجي.

لو تحب، الخطوة الجاية نطبّق نفس نمط الاستثناءات والـ handlers على جزء تاني من mini‑RAG (زي data pipeline: Mongo/chunks/assets)، بحيث يبقى عندك طبقة errors موحدة لكل الـ system.

# PromptBuilder layer عشان ال prompts تبقى under control.

طبقة **PromptBuilder** هي abstraction بسيطة لكنها قوية: تطلع كل منطق بناء الـ prompts من الراوترات، وتخلي عندك مكان واحد تتحكم منه في الأسلوب، اللغة، التعليمات، والتوكن budget.

***

## 1) ما الهدف من PromptBuilder؟

- بدل ما تكتب prompt خام في كل endpoint، يكون عندك:
    - templates جاهزة (Q\&A، تلخيص، ترجمة، إلخ).
    - مكان واحد تعدّل فيه الـ system instructions.
    - تحكم أفضل في حجم الـ context وترتيب الرسائل.

في mini‑RAG مثلاً، أهم use-case:

- سؤال المستخدم عن مشروع معين:
    - سياق = مجموعة chunks من Mongo.
    - سؤال = query.
    - عايز prompt ثابت ومحترم لكل العملاء.

***

## 2) تصميم بسيط لطبقة PromptBuilder

### ملف `stores/llm/prompt_builder.py`

```python
# src/stores/llm/prompt_builder.py
from typing import List, Dict, Literal

from .LLMEnums import OpenAIEnums

Role = Literal["system", "user", "assistant"]


DEFAULT_QA_SYSTEM_INSTRUCTIONS = (
    "أنت مساعد ذكي يجيب عن الأسئلة بدقة اعتمادًا على السياق التالي فقط.\n"
    "لا تخترع معلومات غير موجودة في السياق.\n"
    "لو لم تجد الإجابة في السياق، قل أنك لا تعرف."
)


def build_system_message(content: str) -> Dict:
    return {
        "role": OpenAIEnums.SYSTEM.value,
        "content": content,
    }


def build_user_message(content: str) -> Dict:
    return {
        "role": OpenAIEnums.USER.value,
        "content": content,
    }


def build_assistant_message(content: str) -> Dict:
    return {
        "role": OpenAIEnums.ASSISTANT.value,
        "content": content,
    }
```

**قرارات:**

- helpers صغيرة لبناء messages بشكل consistent.
- تستخدم `OpenAIEnums` عشان ما تنتشر الـ strings (`"system"`, `"user"`) في كل مكان.[^26_1]


### Template لـ Q\&A فوق الـ chunks

```python
def build_qa_messages(
    question: str,
    context_chunks: List[str],
    system_instructions: str = DEFAULT_QA_SYSTEM_INSTRUCTIONS,
) -> List[Dict]:
    """
    يبني قائمة messages (system + user) لسؤال/جواب مبني على context.
    """
    context_text = "\n\n".join(
        f"- {chunk.strip()}" for chunk in context_chunks if chunk.strip()
    )

    user_content = (
        f"السياق التالي يحتوي على معلومات قد تساعد في الإجابة عن السؤال.\n"
        f"السياق:\n{context_text}\n\n"
        f"السؤال:\n{question}"
    )

    messages: List[Dict] = [
        build_system_message(system_instructions),
        build_user_message(user_content),
    ]
    return messages
```

**الشرح:**

- `context_chunks: List[str]`:
    - النصوص اللي طلعتها من Mongo (أو vector DB) لكل سؤال.[^26_2]
- `context_text`:
    - يجمعها في نص واحد، مع تنسيق بسيط (`- chunk`) لتسهيل القراءة على الموديل.[^26_1]
- `user_content`:
    - يوضح بشكل صريح إن “السياق التالي” هو مصدر الحقيقة، ثم يضع السؤال في آخره.[^26_1]
- النتيجة:
    - `messages` جاهزة تدخل مباشرة في `generate_text` كـ `chat_history`.

## 3) استخدام PromptBuilder في الراوتر `/ask/{project_id}`

### مثال Endpoint

```python
# src/routes/ask.py
from fastapi import APIRouter, Request, Depends, HTTPException
from typing import List

from stores.llm.interfaces import TextGeneratorInterface
from dependencies.llm import get_generation_client
from stores.llm.prompt_builder import build_qa_messages
from models.ask import AskRequest, AskResponse
from models.chunk import ChunkModel

router = APIRouter()


@router.post("/ask/{project_id}", response_model=AskResponse)
async def ask_endpoint(
    project_id: str,
    body: AskRequest,
    request: Request,
    generation_client: TextGeneratorInterface = Depends(get_generation_client),
):
    # 1) هات الشنكس الخاصة بالمشروع (مثال مبسط)
    db_client = request.app.state.db_client
    chunk_model = await ChunkModel.create_instance(db_client=db_client)
    chunks = await chunk_model.get_chunks_by_project_id(
        project_id=project_id,
        limit=body.top_k,
    )

    if not chunks:
        raise HTTPException(status_code=400, detail="No chunks found for this project")

    context_chunks: List[str] = [c.chunk_text for c in chunks]

    # 2) بناء الـ messages باستخدام PromptBuilder
    messages = build_qa_messages(
        question=body.question,
        context_chunks=context_chunks,
    )

    # 3) استدعاء LLM
    answer = await generation_client.generate_text(
        prompt="",            # كل شيء موجود في chat_history
        chat_history=messages,
        max_output_tokens=body.max_tokens,
        temperature=body.temperature,
    )

    if not answer:
        raise HTTPException(status_code=502, detail="LLM returned no answer")

    return AskResponse(
        answer=answer,
        context_chunks=context_chunks,
    )
```

**قرارات:**

- الراوتر نفسه بقى بسيط:
    - يجيب الـ chunks.
    - يبني messages عبر `build_qa_messages`.
    - ينادي `generate_text` بدون ما يكتب prompt logic بنفسه.[^26_1]
- أي تعديل في prompt (لغة، صياغة، تعليمات) يحصل في ملف واحد فقط: `prompt_builder.py`.

## 5) ربط PromptBuilder بالـ token budget

لو حابب تدمج token budget في prompt building (قبل call)، تقدر تستخدم `count_tokens` من `token_utils.py`.

### مثال: قطع السياق بحيث لا يتخطّى حدًّا معينًا من التوكنز

```python
from stores.llm.token_utils import count_tokens

def build_qa_messages_with_budget(
    question: str,
    context_chunks: List[str],
    token_budget: int,
    model_name: str,
    system_instructions: str = DEFAULT_QA_SYSTEM_INSTRUCTIONS,
) -> List[Dict]:
    """
    يبني messages مع احترام token_budget للسياق + السؤال.
    """
    selected_chunks: List[str] = []
    used_tokens = count_tokens(question, model_name=model_name)

    for chunk in context_chunks:
        chunk = chunk.strip()
        if not chunk:
            continue
        chunk_tokens = count_tokens(chunk, model_name=model_name)
        if used_tokens + chunk_tokens > token_budget:
            break
        selected_chunks.append(chunk)
        used_tokens += chunk_tokens

    return build_qa_messages(
        question=question,
        context_chunks=selected_chunks,
        system_instructions=system_instructions,
    )
```

**الشرح:**

- `token_budget`: عدد التوكنز المتاحة للسياق + السؤال (قبل الـ system message).
- يمشي على الشنكس واحدة واحدة ويضيفها حتى لا يتجاوز الـ budget.
- بعد كده يبني نفس template الأساسي.[^26_3]

ده مهم خصوصًا لو:

- تستعمل models بحجم context محدود.
- أو عايز تتحكم في التكلفة بدقّة.

# RequestID + تحسين logging (لما تبتدي deploy على بيئة حقيقية)

أفضل طريقة تربط بها logging بالـ requests في الإنتاج هي إضافة **Request ID middleware** + **LoggerAdapter**، عشان كل log من أي provider أو layer يبقى عليه نفس الـ request_id وتقدر تتبعه بسهولة.

***

## 1) RequestID Middleware

### ملف `middleware/request_id.py`

```python
# src/middleware/request_id.py
import uuid
from fastapi import Request
from starlette.middleware.base import BaseHTTPMiddleware


class RequestIDMiddleware(BaseHTTPMiddleware):
    """
    يضيف X-Request-ID لكل request (لو مش موجود)،
    ويحفظه في request.state.request_id لكي تستخدمه في الـ logging.
    """

    async def dispatch(self, request: Request, call_next):
        # 1) لو الكلاينت بعت X-Request-ID، استخدمه، وإلا أنشئ واحد جديد
        request_id = request.headers.get("X-Request-ID") or str(uuid.uuid4())
        request.state.request_id = request_id

        # 2) استدعاء باقي السلسلة
        response = await call_next(request)

        # 3) إرجاع الـ request_id في الهيدر للـ client
        response.headers["X-Request-ID"] = request_id
        return response
```

**القرارات:**

- لو microservice تاني أو gateway بيضيف `X-Request-ID`، نحترمه ونكمله.
- لو request جاي من client مباشر → نولد ID جديد (`uuid4`).
- تخزينه في `request.state.request_id` يخليك توصله من أي dependency أو endpoint.


### تفعيل الـ middleware في `main.py`

```python
# src/main.py
from fastapi import FastAPI
from middleware.request_id import RequestIDMiddleware

app = FastAPI(...)

app.add_middleware(RequestIDMiddleware)
```


***

## 2) LoggerAdapter لإضافة request_id تلقائيًا في logs

بدل ما تبعت request_id يدويًا في كل log، استخدم `logging.LoggerAdapter`.

### ملف `logging_utils.py`

```python
# src/monitoring/logging_utils.py
import logging
from typing import Any, Mapping


class RequestLoggerAdapter(logging.LoggerAdapter):
    """
    يضيف request_id (وحقول أخرى) تلقائيًا لكل message.
    """

    def process(self, msg: str, kwargs: Mapping[str, Any]):
        extra = self.extra.copy()
        extra.update(kwargs.get("extra", {}))

        # دمج request_id في رسالة النص أو في extra حسب الـ formatter
        kwargs["extra"] = extra
        return msg, kwargs
```


### إعداد الـ root logger مع formatter يدعم request_id

مثال بسيط في `logging.conf` أو setup في `main.py`:

```python
import logging
import sys

LOG_FORMAT = (
    "%(asctime)s | %(levelname)s | %(name)s | request_id=%(request_id)s | %(message)s"
)

def setup_logging():
    handler = logging.StreamHandler(sys.stdout)
    formatter = logging.Formatter(LOG_FORMAT)
    handler.setFormatter(formatter)

    root_logger = logging.getLogger()
    root_logger.setLevel(logging.INFO)
    root_logger.addHandler(handler)
```

في `main.py`:

```python
setup_logging()
```

**ملاحظة:**
لو ما فيش `request_id` في extra، الـ formatter هيكسر. حل بسيط:

- تضيف default `request_id` في LoggerAdapter (مثلاً `"-"`)
- أو تستخدم logging `Filter` يضمن حقل `request_id` دائمًا.

Filter بسيط:

```python
class RequestIDFilter(logging.Filter):
    def filter(self, record):
        if not hasattr(record, "request_id"):
            record.request_id = "-"
        return True
```

وتضيفه على الـ handler:

```python
handler.addFilter(RequestIDFilter())
```

```python
# src/models/asset.py (أو stores/models/asset_model.py)
from motor.motor_asyncio import AsyncIOMotorClient
from bson import ObjectId
from stores.db.errors import NotFoundError, PersistenceError

class AssetModel:
    def __init__(self, collection):
        self.collection = collection

    @classmethod
    async def create_instance(cls, db_client: AsyncIOMotorClient):
        return cls(db_client["mini-rag"]["assets"])

    async def get_asset_or_raise(self, asset_id: str):
        try:
            oid = ObjectId(asset_id)
        except Exception as e:
            raise NotFoundError(f"Invalid asset_id format: {asset_id}") from e

        try:
            doc = await self.collection.find_one({"_id": oid})
        except Exception as e:
            # مشكلة في الاتصال بـ Mongo
            raise PersistenceError(f"Mongo error while fetching asset {asset_id}") from e

        if not doc:
            raise NotFoundError(f"Asset not found: {asset_id}")

        # هنا ترجع Pydantic model أو dict
        return doc
```

## 3) Spans مخصصة لـ LLM calls وMongo queries

### أ) LLM Providers: span لكل generate/embed

```python
# src/stores/llm/providers/OpenAIProvider.py
from opentelemetry import trace
from ..LLMEnums import OpenAIEnums
from ..errors import LLMProviderError, LLMConfigError

tracer = trace.get_tracer(__name__)

class OpenAIProvider(...):

    async def generate_text(...):
        if not self.ensure_generation_ready():
            raise LLMConfigError("OpenAI generation model is not set")

        chat_history = chat_history or []
        chat_history.append(
            self.construct_prompt(prompt=prompt, role=OpenAIEnums.USER.value)
        )

        max_tokens = max_output_tokens or self.default_generation_max_output_tokens
        temp = temperature or self.default_generation_temperature

        async def _call() -> Optional[str]:
            # span خاص بالـ LLM call
            with tracer.start_as_current_span(
                "llm.generate_text",
                attributes={
                    "llm.provider": "openai",
                    "llm.operation": "generate",
                    "llm.model": self.generation_model_id or "",
                    "llm.max_tokens": max_tokens,
                    "llm.temperature": temp,
                },
            ) as span:
                try:
                    response = await self.client.chat.completions.create(
                        model=self.generation_model_id,
                        messages=chat_history,
                        max_tokens=max_tokens,
                        temperature=temp,
                    )
                except Exception as e:
                    span.record_exception(e)
                    span.set_status(
                        trace.Status(
                            status_code=trace.StatusCode.ERROR,
                            description=str(e),
                        )
                    )
                    raise LLMProviderError(f"OpenAI generate_text failed: {e}") from e

                if not response or not response.choices:
                    span.set_status(
                        trace.Status(
                            status_code=trace.StatusCode.ERROR,
                            description="Empty choices",
                        )
                    )
                    raise LLMProviderError("OpenAI returned empty choices")

                message = response.choices[^29_0].message
                content = message.get("content") if isinstance(message, dict) else getattr(
                    message, "content", None
                )
                if not content:
                    span.set_status(
                        trace.Status(
                            status_code=trace.StatusCode.ERROR,
                            description="Empty content",
                        )
                    )
                    raise LLMProviderError("OpenAI returned empty content")

                # ممكن تضيف usage لو متاح
                usage = getattr(response, "usage", None)
                if usage:
                    span.set_attribute("llm.usage.prompt_tokens", getattr(usage, "prompt_tokens", 0))
                    span.set_attribute("llm.usage.completion_tokens", getattr(usage, "completion_tokens", 0))

                return content

        return await async_retry_with_backoff(_call, retries=3, base_delay=0.5, max_delay=4.0)
```

**قرارات:**

- `tracer.start_as_current_span("llm.generate_text", attributes={...})`:
    - span child من span الـ HTTP request الحالي.
- attributes:
    - provider, operation, model, max_tokens, temperature → تقدر ترسم إحصائيات per model/provider.
- `record_exception` + `set_status`:
    - تخلي trace viewer (Jaeger/Tempo) يhighlight الـ span كـ error مع تفاصيله.[^29_2]

نفس المبدأ لـ `embed_text` (operation = "embed")، ولـ Cohere/Ollama.

```python
from stores.db.errors import NotFoundError, PersistenceError

tracer = trace.get_tracer(__name__)

class ChunkModel:
    ...

    async def get_chunks_by_project_id(self, project_id: str, limit: int = 5):
        from bson import ObjectId
        try:
            pid = ObjectId(project_id)
        except Exception as e:
            raise NotFoundError(f"Invalid project_id: {project_id}") from e

        with tracer.start_as_current_span(
            "mongo.get_chunks_by_project_id",

                "db.collection": "data_chunks",
                "project.id": str(pid),
                "query.limit": limit,
            },

            try:
                cursor = self.collection.find({"chunk_project_id": pid}).limit(limit)
                records = await cursor.to_list(length=limit)
            except Exception as e:
                span.record_exception(e)
                span.set_status(
                    trace.Status(
                        status_code=trace.StatusCode.ERROR,
                        description=str(e),
                    )
                )
                raise PersistenceError(
                    f"Mongo error while fetching chunks for project {project_id}"
                ) from e

        return [DataChunk(**r) for r in records]
```

- تقدر تشوف في trace:

- تقيس latency لكل مستوى، وتعرف bottlenecks (Mongo queries بطيئة، LLM calls بطيئة، إلخ).

***

## 4) ربط traces مع logging + request_id

### LoggingInstrumentation

استخدمناه بالفعل:

```python
LoggingInstrumentation().instrument(set_logging_format=True)
```

ده يخلي كل log record يحمل تلقائيًا:

- trace_id
- span_id

مع `RequestIDMiddleware`، بقى عندك:

- `request_id` (خاص بك).
- `trace_id/span_id` (من OpenTelemetry).

يمكن تعديل الـ log format لاحتواء الاثنين:

```python
LOG_FORMAT = (
    "%(asctime)s | %(levelname)s | %(name)s | "
    "trace_id=%(otelTraceID)s span_id=%(otelSpanID)s request_id=%(request_id)s | "
    "%(message)s"
)
```

**شرح:**

- `otelTraceID` و`otelSpanID` تضاف تلقائيًا بواسطة `LoggingInstrumentation`.
- `request_id` يأتي من LoggerAdapter / Filter كما وضّحنا قبل.

بهذا الشكل:

- لو عندك log error:
    - تقدر تقفز للـ trace في Jaeger/Tempo بالـ trace_id.
    - تقدر تدور على كل logs لنفس الطلب بـ request_id.

***

## 5) ماذا تحتاج في البنية التحتية؟

- تشغيل OpenTelemetry Collector أو Jaeger all-in-one:
    - Collector يستقبل الـ OTLP traces من التطبيق (`http://localhost:4318/v1/traces`).[^29_1]
    - يصدر لـ Jaeger/Tempo/Zipkin، حسب ما تختار.[^29_2]
- في التطوير:
    - ممكن تستخدم Jaeger Docker image بسيط، وتربطه بالcollector.

***

## الخلاصة العملية

بعد هذه الإضافات:

- كل HTTP request → span.
- كل call LLM → span داخل الـ request، مع model / tokens / errors.
- كل Mongo query مهم → span مع collection/operation.
- الـ logs مربوطة بـ request_id + trace_id / span_id.

ده بيديّك **صورة كاملة** لأي مشكلة performance أو error في mini‑RAG: تفتح trace واحد وتشوف الخط بالكامل من الراوتر لحد LLM وMongo.

لو حابب، في الخطوة الجاية ممكن نرسم flow مختصر لطلب `/ask/{project_id}` في شكل pseudo-trace (tree) يوضح spans والattributes، عشان تبقى شايفها في دماغك قبل ما تطبّق.

```python
@data_router.post("/upload/{project_id}")
async def upload_data(
    request: Request,
    project_id: str,
    file: UploadFile,
    app_settings: Settings = Depends(get_settings),
):
    """
    يرفع ملف واحد لمشروع معيّن:
    - يتحقّق من صلاحية الملف (النوع/الحجم)
    - يحفظه على الـ filesystem
    - ينشئ Asset في Mongo
    """

    # 1) التأكد من وجود المشروع (أو إنشائه)
    project_model = await ProjectModel.create_instance(
        db_client=request.app.db_client
    )
    project = await project_model.get_project_or_create_one(project_id=project_id)
    # لو فيه خطأ في Mongo نفسه، نفترض ProjectModel يرفع PersistenceError

    # 2) التحقق من خصائص الملف
    data_controller = DataController()
    is_valid, result_signal = data_controller.validate_uploaded_file(file=file)
    if not is_valid:
        # هنا validation داخلي (حجم/نوع) → نرجع 400 لكن باستخدام signal
        return JSONResponse(
            status_code=status.HTTP_400_BAD_REQUEST,
            content={"signal": result_signal},
        )

    # 3) حساب المسار النهائي للملف
    project_dir_path = ProjectController().get_project_path(project_id=project_id)
    # تأكد أن الفولدر موجود
    os.makedirs(project_dir_path, exist_ok=True)

    file_path, file_id = data_controller.generate_unique_filepath(
        orig_file_name=file.filename,
        project_id=project_id,
    )

    # 4) كتابة الملف على الديسك
    try:
        async with aiofiles.open(file_path, "wb") as f:
            while chunk := await file.read(app_settings.FILE_DEFAULT_CHUNK_SIZE):
                await f.write(chunk)
    except Exception as e:
        logger.exception("Error while uploading file to disk: %s", e)
        # ممكن نستخدم ResponseSignal خاص بالفشل في الرفع كما في الكود الأصلي
        return JSONResponse(
            status_code=status.HTTP_400_BAD_REQUEST,
            content={"signal": ResponseSignal.FILE_UPLOAD_FAILED.value},
        )

    # 5) تخزين Asset في Mongo
    asset_model = await AssetModel.create_instance(
        db_client=request.app.db_client
    )

    asset_resource = Asset(
        asset_project_id=project.id,
        asset_type=AssetTypeEnum.FILE.value,
        asset_name=file_id,
        asset_size=os.path.getsize(file_path),
    )

    try:
        asset_record = await asset_model.create_asset(asset=asset_resource)
    except Exception as e:
        # أي مشكلة في Mongo → PersistenceError منطقيًا، لكن هنا نحافظ على behaviour بسيط
        logger.exception("Error while saving asset to Mongo: %s", e)
        # ممكن أيضًا نحذف الملف من الديسك rollback بسيط
        return JSONResponse(
            status_code=status.HTTP_500_INTERNAL_SERVER_ERROR,
            content={"signal": ResponseSignal.FILE_UPLOAD_FAILED.value},
        )

    return JSONResponse(
        content={
            "signal": ResponseSignal.FILE_UPLOAD_SUCCESS.value,
            "file_id": str(asset_record.id),
        }
    )
```

**أهم الفروق:**

- استخدمنا `os.makedirs` لضمان وجود مجلد المشروع.
- استخدمنا `logger.exception` بدلاً من `logger.error` لكتابة stack trace.
- تركنا validation الخاص بالملف كما هو لأنه domain logic وليس Mongo error.

## 1) شكل الـ Trace كـ Tree

```text
Span: HTTP GET /api/v1/ask/{project_id}
  attributes:
    http.method = "POST"
    http.route = "/api/v1/ask/{project_id}"
    http.target = "/api/v1/ask/123?..."
    http.status_code = 200
    service.name = "mini-rag"
    request.id = "<request_id from middleware>"

  ├─ Span: mongo.get_project_by_id
  │    attributes:
  │      db.system = "mongodb"
  │      db.operation = "find"
  │      db.collection = "projects"
  │      project.id = "123"
  │      db.statement = '{"_id": ObjectId("...")}' (اختياري/مختصر)
  │      outcome = "success"
  │
  ├─ Span: mongo.get_chunks_by_project_id
  │    attributes:
  │      db.system = "mongodb"
  │      db.operation = "find"
  │      db.collection = "data_chunks"
  │      project.id = "123"
  │      query.limit = 5
  │      outcome = "success"
  │
  ├─ Span: llm.build_prompt (اختياري لو حابب)
  │    attributes:

  │
  └─ Span: llm.generate_text

         llm.provider = "openai"

         llm.model = "gpt-4.1-mini"
         llm.max_tokens = 512

         llm.total_tokens = 1020
         outcome = "success"
```

## 2) التسلسل الزمني للـ spans (من وجهة نظر التنفيذ)

1) **HTTP span** (FastAPIInstrumentor):
    - يبدأ أول ما الريكوست يدخل.
    - يحمل `http.*` attributes + `request_id` في logs.
2) **mongo.get_project_by_id**:
    - داخل `ProjectModel.get_project_or_create_one`.
    - child span من HTTP span.
3) **mongo.get_chunks_by_project_id**:
    - في `ChunkModel.get_chunks_by_project_id` للـ retrieval.
4) **llm.build_prompt** (اختياري):
    - في `build_qa_messages_with_budget` لو حابب ترصده.
    - يساعدك تعرف وقت بناء الـ context نفسه لو عندك عمليات تقطيع/فلترة تقيلة.
5) **llm.generate_text**:
    - في `OpenAIProvider.generate_text`.
    - child span يحتوي:
        - config attributes (model, temperature, max_tokens).
        - usage (prompt_tokens, completion_tokens) لو متاحة.
        - status/error لو حصل exception.
6) **HTTP span ينتهي** بعد بناء الـ response وإرساله.

***

## 3) الربط مع logging

أي log جوه هذا الفلو هيبقى داخل context الـ HTTP span:

- logger يظهر مثلًا:

```text
2026-01-21T16:00:00Z | INFO | routes.ask | trace_id=abc span_id=def request_id=XYZ | Starting ask flow project_id=123
2026-01-21T16:00:00Z | INFO | models.chunk | trace_id=abc span_id=ghi request_id=XYZ | Retrieved 5 chunks for project 123
2026-01-21T16:00:01Z | INFO | providers.OpenAIProvider | trace_id=abc span_id=jkl request_id=XYZ | Calling OpenAI generate_text model=gpt-4.1-mini
```

- من `trace_id=abc` تقدر تفتح trace كامل في Jaeger/Tempo وتشوف الشجرة اللي فوق.
- من `request_id=XYZ` تقدر تربط بين logs من خدمات أخرى (لو عندك gateway / frontend).

***

## 4) شكل trace عند حدوث خطأ

لو، مثلًا، OpenAI رجّع Rate Limit:

```python
    response_model=AskResponse,
)
async def ask_endpoint(
    project_id: str,
    body: AskRequest,
    request: Request,
    generation_client: TextGeneratorInterface = Depends(get_generation_client),
):
    """
    يجيب عن سؤال مستخدم بناءً على chunks المشروع المحددة.
    """

    db_client = request.app.state.db_client

    # 1) التأكد من أن المشروع موجود
    project_model = await ProjectModel.create_instance(db_client=db_client)
    project = await project_model.get_project_or_raise(project_id=project_id)
    # get_project_or_raise متوقع يرمي NotFoundError لو المشروع مش موجود

    # 2) استرجاع الشنكس (context) من Mongo
    chunk_model = await ChunkModel.create_instance(db_client=db_client)

    try:
        chunks: List[DataChunk] = await chunk_model.get_chunks_by_project_id(
            project_id=project.id,
            limit=body.top_k,
        )
    except Exception as e:
        # أي مشكلة في Mongo:
        raise PersistenceError(f"Error while fetching chunks for project {project_id}: {e}") from e

    if not chunks:
        # مفيش سياق للمشروع
        raise NotFoundError(f"No chunks found for project {project_id}")

    context_chunks: List[str] = [c.chunk_text for c in chunks]

    # 3) حساب token_budget (اختياري)
    # مثلاً: input context <= 2000 tokens قبل السؤال
    token_budget = body.context_token_budget or 2000
    model_name = body.model_id or "gpt-4.1-mini"

    messages = build_qa_messages_with_budget(
        question=body.question,
        context_chunks=context_chunks,
        token_budget=token_budget,
        model_name=model_name,
    )

    # ممكن تضبط max_tokens وtemperature من body أو defaults
    max_tokens = body.max_tokens or 512
    temperature = body.temperature or 0.1

    # 4) Call LLM (هنا LLMConfigError / LLMProviderError / LLMError هيطلعوا للـ handlers العامة)
    answer = await generation_client.generate_text(
        prompt="",           # كل شيء بالفعل داخل messages
        chat_history=messages,
        max_output_tokens=max_tokens,
        temperature=temperature,
    )

    if not answer:
        # لو provider رجّع None بدون ما يرمي استثناء (لو لسه عامله كده)
        raise LLMError("Generation client returned no answer")

    # 5) تجهيز الرد
    return AskResponse(
        answer=answer,
        context_chunks=context_chunks,
        signal=ResponseSignal.ANSWER_SUCCESS.value,
    )
```


***

## 3) توحيد التعامل مع الأخطاء عبر handlers

بما إن عندك handlers مركزية:

- `NotFoundError` → 404 JSON (مثلاً `{"signal": "NOT_FOUND", ...}`).[^32_1]
- `PersistenceError` → 500 JSON (`"PERSISTENCE_ERROR"`).[^32_1]
- `LLMProviderError` → 502 JSON (`"LLM_PROVIDER_ERROR"`).[^32_1]
- `LLMConfigError` → 500 (`"LLM_CONFIG_ERROR"`).[^32_1]

الـ endpoint نفسه لا يحتاج:

```python
try:
    ...
except ...:
    ...
```

إلا في مواضع نادرة لو حابب تجمع أخطاء متعددة في رد واحد. غالبية السيناريوهات تساب الاستثناء يطلع ويُمسك في الـ handlers.

```python
import logging
from monitoring.logging_utils import RequestLoggerAdapter
from dependencies.logging import get_request_logger  # اللي عملناه قبل كده

logger = logging.getLogger(__name__)

@ask_router.post(

async def ask_endpoint(

    request: Request,

    request_logger: RequestLoggerAdapter = Depends(get_request_logger),
):
    request_logger.info(
        "Starting ask flow",
        extra={"project_id": project_id},
    )

    ...
    request_logger.info(
        "Retrieved chunks",
        extra={"project_id": project_id, "chunks_count": len(chunks)},
    )

    ...
    request_logger.info(
        "Calling LLM generation",

            "project_id": project_id,
```

كل log يحمل:

- `request_id` (من middleware).
- `trace_id/span_id` (من OpenTelemetry LoggingInstrumentation).

## 5) الشكل النهائي للـ flow /ask/{project_id}

1) HTTP request → FastAPI span.
2) `ProjectModel.get_project_or_raise` → Mongo span (project).
3) `ChunkModel.get_chunks_by_project_id` → Mongo span (chunks).
4) `build_qa_messages_with_budget` → optional span (prompt building).
5) `generation_client.generate_text` → LLM span (OpenAI/Cohere/Ollama).
6) AskResponse JSON.

والـ errors في أي نقطة يتم ترجمتها تلقائيًا عن طريق الـ handlers.

لو تحب، ممكن نعمل لك ملف `dependencies/__init__.py` بسيط يجمع:

- `get_generation_client`
- `get_embedding_client`
- `get_request_logger`

عشان الراوترات تبقى import‑friendly ونظيفة.

تمام، كده عندك تصميم متكامل لطبقة LLM + data + observability في mini‑RAG، تقدر تطبّقه تدريجيًا على المشروع الحقيقي.
