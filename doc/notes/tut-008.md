# Summarize this video

هذا الفيديو حلقة تطبيقية لتحسين **data pipeline** في مشروع mini-RAG قبل الانتقال لمرحلة الـ LLM نفسها.[^1_1]

## فكرة الحلقة

- الهدف هو تحسين طريقة تخزين ومعالجة الملفات (assets) في MongoDB بحيث يمكن التعامل مع أكثر من ملف لكل مشروع، وتجهيز كل ذلك لمرحلة ربطها بالـ RAG لاحقًا.[^1_1]
- التركيز على جعل التعديلات “incremental” بدون إعادة كتابة المشروع من الصفر، مع الحفاظ على تصميم نظيف يسهل التطوير المستقبلي.[^1_1]


## تحسين الـ Assets Model

- إضافة كولكشن assets في الداتابيز لتخزين موقع كل ملف ونوعه (type) بدل افتراض أن المصدر دائمًا ملف واحد فقط، مع دعم أنواع مستقبلية مثل URL أو streams.[^1_1]
- تعديل دوال الـ model بحيث يمكن جلب كل الـ assets لمشروع معيّن مع فلترة بالـ type، وتحويل نتائج Mongo إلى Pydantic models بدل التعامل المباشر مع dicts الخام.[^1_1]


## تطوير Endpoint المعالجة (process)

- جعل `file_id` (اسم الملف) باراميتر اختياري:
    - لو أُرسل → تُعالج فايل واحد محدد.
    - لو لم يُرسل → يُجلب كل الملفات الخاصة بالمشروع من كولكشن assets ويتم عمل loop عليها.[^1_1]
- توحيد منطق المعالجة بحيث يتم التعامل دائمًا مع قائمة من الملفات (حتى لو تحتوي ملفًا واحدًا) لتبسيط الكود وتقليل التكرار في الـ if/else.[^1_1]


## فحوصات السلامة والـ Logging

- إضافة validation للتأكد من وجود الملف فعليًا على الـ filesystem قبل محاولة تحميله (باستخدام `os.path.exists`) ثم التعامل مع حالات الـ `None` في `get_file_content` بشكل صريح.[^1_1]
- استخدام logger بدل `print` لكتابة رسائل error عند فشل معالجة ملف معيّن، مع الاستمرار في معالجة باقي الملفات وفقًا لسيناريو عمل يختاره الـ business logic (مثلاً: تخطي الملف المعطوب مع تسجيل تحذير).[^1_1]


## تحديث الـ Data Schema للـ Chunks

- تعديل سكيمة `data_chunk` بحيث تحتوي على حقل `chunk_asset_id` (ObjectId) يربط كل chunk بالـ asset الأصلي في كولكشن assets، بالإضافة إلى الـ metadata التي تحتوي على `source` (مسار الملف).[^1_1]
- بعد التعديلات يصبح بالإمكان معرفة: من أي ملف جاء كل chunk، وما هو الـ asset (بالـ ObjectId) المرتبط به، مما يسهل لاحقًا عمليات الاسترجاع والتحليل على مستوى الملف.[^1_1]


## معالجة حالات الحافة (Edge Cases)

- التعامل مع حالة إرسال `file_id` غير موجود في الـ DB، بإرجاع JSON Response بخطأ واضح (مثل `file_id_error`) مع status code 400.[^1_1]
- التعامل مع حالة عدم وجود أي ملفات في المشروع (أو أن نتيجة البحث فارغة) برسالة خطأ `no_files_error` توضح أن لا يوجد ما يمكن معالجته.[^1_1]

إذا أحببت، يمكن استخراج pseudo-code مختصر من الحلقة يربط بين الـ endpoints والـ models والـ Mongo لإضافته كـ reference في مشروعك.

## 1) الراوتر `/process`

```python
@router.post("/process")
async def process_endpoint(project_id: str, file_id: str | None = None, request: Request):
    db = request.app.state.db
    assets_model = AssetModel(db)
    chunk_model = ChunkModel(db)

    # 1) تحديد قائمة الـ assets
    if file_id is not None:
        asset = await assets_model.get_by_name(project_id=project_id, name=file_id)
        if asset is None:
            return JSONResponse({"error": "file_id_error"}, status_code=400)
        assets = [asset]
    else:
        assets = await assets_model.get_by_project_id(project_id=project_id)
        if not assets:
            return JSONResponse({"error": "no_files_error"}, status_code=400)

    # 2) لوب على كل asset
    for asset in assets:
        file_path = asset.path
        if not os.path.exists(file_path):
            logger.error(f"File not found: {file_path}")
            continue

        content = get_file_content(file_path)
        if content is None:
            logger.error(f"Cannot read file: {file_path}")
            continue

        chunks = split_to_chunks(content)  # list[str]

        # 3) حفظ الـ chunks في Mongo
        for ch in chunks:
            await chunk_model.insert_chunk(
                project_id=project_id,
                asset_id=asset.id,
                text=ch,
                source=file_path,
            )

    return {"status": "ok"}
```


## 2) AssetModel (Mongo + Pydantic)

```python
class AssetModel:
    def __init__(self, db):
        self.collection = db["assets"]

    async def get_by_project_id(self, project_id: str, type_: str | None = None) -> list[Asset]:
        query = {"project_id": ObjectId(project_id)}
        if type_ is not None:
            query["type"] = type_
        docs = await self.collection.find(query).to_list(length=None)
        return [Asset(**doc) for doc in docs]

    async def get_by_name(self, project_id: str, name: str) -> Asset | None:
        doc = await self.collection.find_one(
            {"project_id": ObjectId(project_id), "name": name}
        )
        return Asset(**doc) if doc else None
```

### كود مبسط للـ endpoint

```python
@router.post("/process")
async def process_endpoint(
    request: Request,
    project_id: str,
    file_id: str | None = None,   # بقى اختياري
):
    db = request.app.state.db
    assets_model = AssetModel(db)
    chunks_model = ChunkModel(db)

    project_file_ids: list[tuple[ObjectId, str]] = []

    if file_id is not None:
        # سيناريو: مستخدم بعت اسم فايل واحد
        asset = await assets_model.get_by_name(project_id=project_id, name=file_id)
        if asset is None:
            return JSONResponse(
                {
                    "signal": "FILE_ID_ERROR",
                    "message": f"File {file_id} not found in assets",
                },
                status_code=400,
            )
        project_file_ids = [(asset.id, asset.name)]
    else:
        # سيناريو: مفيش file_id → هات كل فايلات المشروع
        assets = await assets_model.get_by_project_id(
            project_id=project_id,
            type_="file",
        )
        project_file_ids = [(a.id, a.name) for a in assets]

    # تأكيد إن فيه فايلات أصلًا
    if len(project_file_ids) == 0:
        return JSONResponse(
            {
                "signal": "NO_FILES_ERROR",
                "message": "No files found for this project",
            },
            status_code=400,
        )

    total_records = 0
    processed_files = 0

    for asset_id, file_name in project_file_ids:
        # هنا هيتم جلب المحتوى وعمل chunking وحفظه (هنيجي لها تحت)
        inserted = await process_single_file(
            chunks_model=chunks_model,
            project_id=project_id,
            asset_id=asset_id,
            file_name=file_name,
        )
        total_records += inserted
        processed_files += 1

    return {
        "signal": "OK",
        "files_processed": processed_files,
        "records_inserted": total_records,
    }
```

الفيديو ينبه إن التصميم ده موضع نقاش: ممكن تعمل endpoint منفصل لـ “process all” وآخر لـ “process single file”، أو توحّدهم زي ما هو عامل وتعتمد على optional param، حسب الـ API style اللي هتعتمده.[^4_1]

## فاليديشن لوجود الفايل على الـ filesystem

قبل التعديلات، `get_file_content` كانت بتفترض إن الفايل موجود بمجرد وجود path في الداتابيز.[^4_1]
الآن بقى في check صريح باستخدام `os.path.exists`، ولو الفايل مش موجود ترجع `None` والراوتر يتعامل مع الحالة دي بلوج.[^4_1]

### كود فاليديشن في file loader

```python
import os
from langchain_community.document_loaders import TextLoader, PyPDFLoader

def get_file_loader(file_path: str):
    ext = os.path.splitext(file_path)[^4_1].lower()

    # تأكد إن الفايل أصلًا موجود
    if not os.path.exists(file_path):
        return None

    if ext == ".txt":
        return TextLoader(file_path, encoding="utf-8")
    elif ext == ".pdf":
        return PyPDFLoader(file_path)
    # لاحقًا: أنواع أخرى
    return None


def get_file_content(file_path: str) -> list[str] | None:
    loader = get_file_loader(file_path)
    if loader is None:
        return None

    docs = loader.load()  # LangChain Documents
    return [d.page_content for d in docs]
```


### التعامل مع `None` في الراوتر + logging

```python
import logging

logger = logging.getLogger(__name__)

async def process_single_file(chunks_model, project_id, asset_id, file_name: str) -> int:
    file_path = build_file_path(file_name)  # حسب طريقتك في التخزين

    # لو الفايل مش موجود على الـ FS
    if not os.path.exists(file_path):
        logger.error(f"File not found on disk: {file_path}")
        return 0

    contents = get_file_content(file_path)
    if contents is None:
        logger.error(f"Error while loading file content: {file_path}")
        return 0

    chunks = split_to_chunks(contents)  # تقطيع المحتوى

    inserted = 0
    for ch in chunks:
        await chunks_model.insert_chunk(
            project_id=project_id,
            asset_id=asset_id,
            text=ch,
            source=file_path,
        )
        inserted += 1

    return inserted
```

## إضافة `chunk_asset_id` وربط الـ chunks بالـ asset

- دلوقتي تمت إضافة حقل `chunk_asset_id` من نوع `ObjectId` يشير إلى `_id` بتاع الـ asset في collection `assets`، عشان تقدر تسترجع chunks لكل فايل بسهولة وتعمل تحليل على مستوى الملف.[^4_1]

## إصلاحات الكوبي‑بيست و refactor داخل الـ loop

- كان فيه خطأ: `delete_by_project_id` كانت بتتندَه جوه الـ `for` اللي بيلف على الفايلات، فكل مرة تعالج فايل كانت بتحذف كل الشانكس القديمة ثم تضيف الجديدة، ففعليًا كان بيبقى فايل واحد بس في الآخر.[^4_1]
- التعديل: الـ delete يحصل مرة واحدة قبل الدخول في الـ loop على الفايلات، وبعدها تبدأ تضيف لكل فايل من غير ما تمسح تاني.[^4_1]

## ضبط الـ Models للرجوع بـ Pydantic بدل dict

## lifespan: تهيئة وغلق Mongo داخل FastAPI

```python
@asynccontextmanager
async def lifespan(app: FastAPI):
    client = AsyncIOMotorClient(MONGODB_URI)            # 1
    db = client[MONGODB_DB_NAME]                        # 2
    app.state.db_client = client                        # 3
    app.state.db = db                                   # 4
    try:
        yield                                           # 5
    finally:
        client.close()                                  # 6
```

- السطر 1: إنشاء `AsyncIOMotorClient` باستخدام الـ URI من الـ env؛ ده بيعمل connection pool للـ app.[^5_3]
- السطر 2: اختيار database بعينها من الـ Mongo client، زي `mini_rag`.[^5_3]
- السطر 3: تخزين الـ client في `app.state` عشان يبقى متاح من أي راوتر عبر `request.app.state.db_client`.[^5_3]
- السطر 4: تخزين object الـ db نفسه في `app.state.db` لتسهيل الوصول المباشر للداتابيز بدون إعادة بناء client.[^5_3]
- السطر 5: `yield` هنا بيقول لـ FastAPI “من هنا يبدأ تشغيل التطبيق”، وأي كود قبلها يعتبر startup logic.[^5_3]
- السطر 6: في نهاية حياة التطبيق (shutdown)، بيتم غلق Mongo client وتنظيف الموارد.[^5_3]

نقطة مهمة: استخدام lifespan pattern أفضل من events القديمة (`startup`/`shutdown`) في الإصدارات الحديثة من FastAPI.[^5_3]

## ملف `src/helpers/config.py`

هنا الطبقة اللي بتحوّل `.env` إلى object مضبوط typed تستخدمه في كل المشروع.[^7_1]

```python
from pydantic_settings import BaseSettings, SettingsConfigDict
```

- `BaseSettings`: كلاس من Pydantic v2 مصمم لإدارة configuration من env variables/files.[^7_1]
- `SettingsConfigDict`: طريقة حديثة في Pydantic v2 لتعريف إعدادات الـ Config بدل الكلاس الداخلي القديم.[^7_1]


### كلاس Settings

```python
class Settings(BaseSettings):
    APP_NAME: str
    APP_VERSION: str

    OPENAI_API_KEY: str

    FILE_ALLOWED_TYPES: list
    FILE_MAX_SIZE: int
    FILE_DEFAULT_CHUNK_SIZE: int

    MONGODB_URL: str
    MONGODB_DATABASE: str

    GENERATION_BACKEND: str
    EMBEDDING_BACKEND: str

    OPENAI_API_KEY: str = None
    OPENAI_API_URL: str = None
    COHERE_API_KEY: str = None

    GENERATION_MODEL_ID: str = None
    EMBEDDING_MODEL_ID: str = None
    EMBEDDING_MODEL_SIZE: int = None

    INPUT_DAFAULT_MAX_CHARACTERS: int = None
    GENERATION_DAFAULT_MAX_TOKENS: int = None
    GENERATION_DAFAULT_TEMPERATURE: float = None
```

شرح النقاط important:

- `class Settings(BaseSettings)`: أي attribute هنا بيتملأ أوتوماتيك من env vars اللي لها نفس الاسم (by default).[^7_1]
- `APP_NAME`, `APP_VERSION`: لازم يتوفروا (مفيش default)، وإلا Pydantic هيرفع error عند إنشاء Settings.[^7_1]
- `FILE_ALLOWED_TYPES: list`: هتتشال من env كـ string، وPydantic يحاول يحوّلها لـ list؛ غالبًا بيستخدم JSON-like syntax في `.env` (زي `["text/plain","application/pdf"]`).[^7_1]
- `MONGODB_URL`, `MONGODB_DATABASE`: نفس القيم اللي عرفتها في `.env.example`.[^7_1]

لاحظ: فيه تكرار لـ `OPENAI_API_KEY` مرة بدون default ومرة بـ `= None`؛ ده واضح إنه glitch بسيط في الفرع ده، وفي الفروع الأحدث بيتصلّح بتعريف واحد فقط.[^7_3][^7_1]

المجموعة الأخيرة:

- `GENERATION_MODEL_ID`, `EMBEDDING_MODEL_ID`, `EMBEDDING_MODEL_SIZE`: إعدادات الموديلات نفسها؛ قيمهم من `.env`.[^7_1]
- `INPUT_DAFAULT_MAX_CHARACTERS`, `GENERATION_DAFAULT_MAX_TOKENS`, `GENERATION_DAFAULT_TEMPERATURE`: نفس القيم اللي عرفتها في `.env.example`, لكن optional في الكود (default = None) عشان تقدر تحط defaults في أماكن أخرى لو حبيت.[^7_1]


### Config الداخلي (مصدر env)

```python
    class Config:
        env_file = ".env"
```

- بيقول لـ Pydantic إن مصدر الإعدادات ملف `.env` في root الـ project، بالإضافة إلى الـ env variables الموجودة في الـ system.[^7_1]
- ترتيب الأولوية: env vars في النظام > القيم الموجودة في `.env` > الـ defaults المكتوبة في الكلاس.[^7_1]

في Pydantic v2، الشكل الرسمي بقى:

```python
model_config = SettingsConfigDict(env_file=".env")
```

بدل class Config؛ لكن في الفرع ده لسه مستخدم style v1، وغالبًا هيتم تحديثه في فروع لاحقة.[^7_1]

### دالة get_settings

```python
def get_settings():
    return Settings()
```

- دي abstraction بسيطة عشان ما تنشئش `Settings()` كل مرة بإيدك في كل ملف.[^7_1]
- في `main.py` أو في أي راوتر هتستعملها كده:

```python
from helpers.config import get_settings

settings = get_settings()
print(settings.MONGODB_URL)
```

- Pydantic بيعمل internal caching عادةً (أو ممكن تضيف caching بنفسك) عشان ما يعيدش قراءة `.env` ألف مرة، لكن حتى لو ما فيش caching، حجم الإعدادات صغير جدًا.[^7_1]

- `get_settings`: يجيب object الإعدادات اللي شرحناه من `.env` (Mongo, LLM, files...).[^8_1]
- `LLMProviderFactory`: factory بترجع client مناسب حسب الـ backend (OpenAI, Cohere, ...).[^8_1]
- `app = FastAPI()`: إنشاء instance واحدة global يستخدمها Uvicorn/Docker.[^8_1]


## دالة startup_db_client

```python

    app.mongo_conn = AsyncIOMotorClient(settings.MONGODB_URL)
    app.db_client = app.mongo_conn[settings.MONGODB_DATABASE]
```

- `settings = get_settings()`:

- `app.mongo_conn = AsyncIOMotorClient(settings.MONGODB_URL)`:
    - ينشئ connection pool لـ Mongo باستخدام الـ URL اللي في الإعدادات (من `.env.example`: `MONGODB_URL`).[^8_1]

- `llm_provider_factory = LLMProviderFactory(settings)`:
    - ينشئ factory واحدة بتعرف من الإعدادات انت عايز تستخدم أي providers (OpenAI/Cohere...).[^8_1]

# اكمل

هكمل دلوقتي طبقة الـ LLM abstraction: الـ interface، الـ enums، والـ factory اللي بتوصلهم بالإعدادات اللي في `.env`.[^9_1]

## LLMInterface: عقد موحّد لكل مزوّد

```python
from abc import ABC, abstractmethod

class LLMInterface(ABC):

    @abstractmethod
    def set_generation_model(self, model_id: str):
        pass

    @abstractmethod
    def set_embedding_model(self, model_id: str, embedding_size: int):
        pass

    @abstractmethod
    def generate_text(self, prompt: str, chat_history: list = [], max_output_tokens: int = None, temperature: float = None):
        pass

    @abstractmethod
    def embed_text(self, text: str, document_type: str = None):
        pass

    @abstractmethod
    def construct_prompt(self, prompt: str, role: str):
        pass
```

سطر‑بسطر:

- `from abc import ABC, abstractmethod`: استيراد الـ base class للأصناف المجردة (abstract) والـ decorator `@abstractmethod`.[^9_1]
- `class LLMInterface(ABC)`:
    - تعريف interface مجرد (مافيهوش implementation حقيقي)، يجبر أي provider (OpenAI, Cohere, ... ) يطبّق نفس الـ contract.[^9_1]

الميثودز:

- `set_generation_model(self, model_id: str)`:
    - كل provider لازم يعرف يضبط موديل التوليد (مثلاً يختار `gpt-3.5-turbo-0125` أو موديل Cohere المناسب).[^9_1]
- `set_embedding_model(self, model_id: str, embedding_size: int)`:
    - نفس الفكرة لكن للـ embeddings، مع تمرير حجم الـ vector (384 مثلاً).[^9_2]
- `generate_text(...)`:
    - abstraction لـ call الجينيريشن. البراميترز:
        - `prompt`: النص الأساسي أو الـ system prompt.[^9_1]
        - `chat_history: list = []`: تاريخ المحادثة (قائمة رسائل) يختلف تمثيلها بين OpenAI/Cohere، لكن الـ interface يفرض عليك تقبّله.[^9_1]
        - `max_output_tokens`: سقف الـ tokens للرد.
        - `temperature`: درجة العشوائية في الرد.[^9_1]
- `embed_text(self, text: str, document_type: str = None)`:
    - abstraction لعمل embedding لنص واحد؛ `document_type` ممكن يكون `"document"` أو `"query"` (هتظهر في `DocumentTypeEnum`).[^9_1]
- `construct_prompt(self, prompt: str, role: str)`:
    - يبني الرسالة بالشكل المناسب للـ provider (OpenAI عنده roles `system/user/assistant`، Cohere له صياغة مختلفة).[^9_1]

الفكرة الأساسية:

- كل provider يطبق الـ interface ده، فتقدر تغيّر من OpenAI لـ Cohere أو العكس بدون ما تغير الراوترات؛ بس تغيّر backend في `.env`.[^9_1]

# نعمل endpoint كامل /ask/{project_id} فوق mini-RAG

هنبني endpoint `/ask/{project_id}` كطبقة رفيعة فوق اللي موجود في `tut-008`: ياخد سؤال، يجيب الشنكس من Mongo، يحوّلها لسياق، وينادي LLM abstraction للـ إجابة.[^14_1]

## شكل الـ endpoint المقترح

```python
from fastapi import APIRouter, Request
from pydantic import BaseModel
from models.chunk import ChunkModel

ask_router = APIRouter(prefix="/ask", tags=["ask"])


class AskRequest(BaseModel):
    question: str
    top_k: int = 5


class AskResponse(BaseModel):
    answer: str
    context_chunks: list[str]


@ask_router.post("/{project_id}", response_model=AskResponse)
async def ask_project(request: Request, project_id: str, body: AskRequest):
    db_client = request.app.db_client

    # 1) هات الشنكس الخاصة بالمشروع من Mongo
    chunk_model = await ChunkModel.create_instance(db_client=db_client)
    chunks = await chunk_model.get_chunks_by_project_id(
        project_id=project_id,
        limit=body.top_k,
    )

    if not chunks:
        return AskResponse(answer="لا توجد بيانات متاحة لهذا المشروع.", context_chunks=[])

    # 2) كوّن سياق نصي من الشنكس
    context_parts = [c.chunk_text for c in chunks]
    context_text = "\n\n".join(context_parts)

    # 3) ابني الـ prompt
    prompt = f"""أنت مساعد ذكي يجيب عن الأسئلة بناءً على السياق التالي فقط.

السياق:
{context_text}

السؤال:
{body.question}

الإجابة بالعربية وبشكل واضح ومختصر، ولو المعلومة غير موجودة في السياق قل إنك لا تعرف ولا تخترع إجابة.
"""

    # 4) نادِي LLM abstraction
    generation_client = request.app.generation_client
    answer = generation_client.generate_text(
        prompt=prompt,
        chat_history=[],
        max_output_tokens=512,
        temperature=0.1,
    )

    if not answer:
        answer = "حدث خطأ أثناء توليد الإجابة."

    return AskResponse(
        answer=answer,
        context_chunks=context_parts,
    )
```

الفيديو ده بيبني طبقة **LLM abstraction كاملة** في mini-RAG: انترفيس موحّد، Providers لـ OpenAI وCohere، Factory لاختيارهم من الـ config، وربطهم في FastAPI lifespan بدل on_event.[^16_1]

## الفكرة المعمارية العامة

- الهدف: تفصل مشروعك عن مزود LLM معين (OpenAI، Cohere، Ollama...) عن طريق واجهة موحدة (Interface) وFactory.[^16_1]
- الـ LLM مسؤول عن مهمتين أساسيتين:
    - **Embedding**: تحويل النصوص إلى vectors للتخزين في vector DB.
    - **Generation**: توليد إجابات نصية من الـ context + السؤال.[^16_1]


## LLMInterface (الانترفيس)

الكود (مكافئ لما في الريبو `LLMInterface.py`):[^16_2]

```python
from abc import ABC, abstractmethod

class LLMInterface(ABC):

    @abstractmethod
    def set_generation_model(self, model_id: str):
        pass

    @abstractmethod
    def set_embedding_model(self, model_id: str, embedding_size: int):
        pass

    @abstractmethod
    def generate_text(
        self,
        prompt: str,
        chat_history: list = [],
        max_output_tokens: int = None,
        temperature: float = None,
    ):
        pass

    @abstractmethod
    def embed_text(self, text: str, document_type: str = None):
        pass

    @abstractmethod
    def construct_prompt(self, prompt: str, role: str):
        pass
```

- يرث من `ABC` عشان يبقى interface حقيقي.[^16_2]
- `set_generation_model` / `set_embedding_model`: لضبط الموديل IDs والـ embedding size في runtime بدل تثبيتهم في `__init__`.[^16_1]
- `generate_text`: abstraction فوق الـ chat/generation API لأي provider (OpenAI/Cohere/غيرهم).[^16_2]
- `embed_text`: abstraction فوق API الـ embeddings، مع `document_type` (document أو query).[^16_1]
- `construct_prompt`: توحيد الشكل الداخلي للرسالة حسب الـ provider (OpenAI: role/content، Cohere: role/text).[^16_2]


## LLMEnums (الثوابت المشتركة)

الكود (مكافئ لـ `LLMEnums.py`):[^16_2]

```python
from enum import Enum

class LLMEnums(Enum):
    OPENAI = "OPENAI"
    COHERE = "COHERE"


class OpenAIEnums(Enum):
    SYSTEM = "system"
    USER = "user"
    ASSISTANT = "assistant"


class CoHereEnums(Enum):
    SYSTEM = "SYSTEM"
    USER = "USER"
    ASSISTANT = "CHATBOT"
    DOCUMENT = "search_document"
    QUERY = "search_query"


class DocumentTypeEnum(Enum):
    DOCUMENT = "document"
    QUERY = "query"
```

- `LLMEnums`: يحدد أسماء الـ backends المدعومة في config والـ Factory.[^16_2]
- `OpenAIEnums`: roles الخاصة بـ OpenAI Chat (`system/user/assistant`).[^16_2]
- `CoHereEnums`: roles + input types الخاصة بكوهير (SYSTEM, USER, CHATBOT, search_document, search_query).[^16_2]
- `DocumentTypeEnum`: نوع النص العام (document أو query) عشان يترجم لـ provider-specific input_type.[^16_1]


## OpenAIProvider (تطبيق الانترفيس لـ OpenAI)

مختصر الكود (من `OpenAIProvider.py`):[^16_2]

```python
from ..LLMInterface import LLMInterface
from ..LLMEnums import OpenAIEnums
from openai import OpenAI
import logging


class OpenAIProvider(LLMInterface):
    def __init__(
        self,
        api_key: str,
        api_url: str = None,
        default_input_max_characters: int = 1000,
        default_generation_max_output_tokens: int = 1000,
        default_generation_temperature: float = 0.1,
    ):
        self.api_key = api_key
        self.api_url = api_url

        self.default_input_max_characters = default_input_max_characters
        self.default_generation_max_output_tokens = default_generation_max_output_tokens
        self.default_generation_temperature = default_generation_temperature

        self.generation_model_id = None
        self.embedding_model_id = None
        self.embedding_size = None

        self.client = OpenAI(api_key=self.api_key, api_url=self.api_url)
        self.logger = logging.getLogger(__name__)
```

- يحفظ الـ API key وURL والـ defaults (limits + temperature).[^16_2]
- يخلق `OpenAI` client واحد reusable.[^16_2]
- يترك model IDs لتُضبط لاحقًا من `main.py` باستخدام `set_generation_model` و `set_embedding_model`.[^16_2]

```python
        default_generation_temperature: float = 0.1,
```

- نفس structure لكن client Cohere.[^16_2]


### generate_text

```python
def generate_text(
    self,
    prompt: str,
    chat_history: list = [],
    max_output_tokens: int = None,
    temperature: float = None,
):
    if not self.client:
        self.logger.error("CoHere client was not set")
        return None

    if not self.generation_model_id:
        self.logger.error("Generation model for CoHere was not set")
        return None

    max_output_tokens = (
        max_output_tokens
        if max_output_tokens
        else self.default_generation_max_output_tokens
    )
    temperature = (
        temperature if temperature else self.default_generation_temperature
    )

    response = self.client.chat(
        model=self.generation_model_id,
        chat_history=chat_history,
        message=self.process_text(prompt),
        temperature=temperature,
        max_tokens=max_output_tokens,
    )
```

- يستخدم `cohere.Client.chat` مع history + message الوحدة.[^16_2]

```python
    if not response or not response.text:
        self.logger.error("Error while generating text with CoHere")
        return None

    return response.text
```

- يرجّع النص مباشرة.[^16_2]

## LLMProviderFactory (الفاكتوري)

الكود (من `LLMProviderFactory.py`):[^16_2]

```python
from .LLMEnums import LLMEnums
from .providers.OpenAIProvider import OpenAIProvider
from .providers.CoHereProvider import CoHereProvider


class LLMProviderFactory:
    def __init__(self, config):
        self.config = config

    def create(self, provider: str):
        if provider == LLMEnums.OPENAI.value:
            return OpenAIProvider(
                api_key=self.config.OPENAI_API_KEY,
                api_url=self.config.OPENAI_API_URL,
                default_input_max_characters=self.config.INPUT_DAFAULT_MAX_CHARACTERS,
                default_generation_max_output_tokens=self.config.GENERATION_DAFAULT_MAX_TOKENS,
                default_generation_temperature=self.config.GENERATION_DAFAULT_TEMPERATURE,
            )

        if provider == LLMEnums.COHERE.value:
            return CoHereProvider(
                api_key=self.config.COHERE_API_KEY,
                default_input_max_characters=self.config.INPUT_DAFAULT_MAX_CHARACTERS,
                default_generation_max_output_tokens=self.config.GENERATION_DAFAULT_MAX_TOKENS,
                default_generation_temperature=self.config.GENERATION_DAFAULT_TEMPERATURE,
            )

        return None
```

- يأخذ `settings` (من `get_settings()` في `helpers/config.py`) كـ config.[^16_2]
- `create("OPENAI")`: يرجّع `OpenAIProvider` مضبوط بكل القيم من `.env` (limits, temperature...).[^16_2]
- `create("COHERE")`: يرجّع `CoHereProvider` بنفس الـ interface.[^16_2]
- باقي الكود (main.py) يستعمله في startup لإنشاء:
    - `app.generation_client`
    - `app.embedding_client`
ويضبط الموديلات من `GENERATION_MODEL_ID` و `EMBEDDING_MODEL_ID`.[^16_2]
